# 地块规格、社区布局与私宅分区

## 面积与边长

地块规格由平面边长和面积描述，面积单位为平方米，边长单位为米。`GroundArea.tab`记录设计预设的长、宽、显示顺序及私人地块标记，面积按长×宽计算。

| 面积（平） | 设计长×宽（米） | 设计入口条件 |
| ---------- | --------------- | ------------ |
| 1,280      | 32 × 40         | 社区规格     |
| 2,240      | 40 × 56         | 社区规格     |
| 4,032      | 56 × 72         | 社区规格     |
| 7,200      | 72 × 100        | 社区规格     |
| 6,272      | 56 × 112        | 私宅预设     |
| 11,648     | 104 × 112       | 私宅预设     |
| 45,792     | 212 × 216       | 完整私宅     |

设计预设不表示玩家已经拥有或解锁相应土地。实际社区地块可旋转，四角坐标决定它在地图中的位置；相同面积不等于同一地址。`HLBOp_Enter.GetArea`在社区/私宅模式读取地块表，在设计模式使用所选长宽乘积。

## 私宅完整布局

私宅基础数据保存一个完整边界和7个分区。以下为平面X、Y方向的实际边长；与设计入口的长宽顺序可以不同。

| 分区 | 面积（平） | 平面X×Y（米） |
| ---- | ---------- | ------------- |
| 1区  | 2,240      | 56 × 40       |
| 2区  | 4,032      | 56 × 72       |
| 3区  | 6,272      | 56 × 112      |
| 4区  | 7,200      | 100 × 72      |
| 5区  | 7,200      | 100 × 72      |
| 6区  | 7,200      | 100 × 72      |
| 7区  | 11,648     | 112 × 104     |
| 全部 | **45,792** | **212 × 216** |

分区图按`.pland`四角坐标绘制，不按面积推测拼接顺序。7区面积相加恰好等于完整边界面积，平面分割验证无重叠和空洞。网页中的“整个私宅”显示所有分区，也可选择一个分区作为布置参考。

`PrivateHomeAreas.tab`提供分区名称、标称面积和解锁相关字段。真实账号的解锁、铲平和除草状态由游戏运行时提供，不能仅凭静态表决定。网页没有读取玩家状态，也不自动按某个等级或消费数值替玩家解锁区域。

私宅外观表有17条外观记录。它们对应同一类私宅的外观选择，该数量不表示同时可用的地块数量；网页仅展示已核对的基础分区，不声称还原全部外观的地形。

## 数据读取过程

1. `settings/MapList.tab`给出地图资源名；`settings/Homeland/HomelandMapList.tab`区分社区与私宅。
2. `LandInfo.txt`提供地块编号、名称和标称面积；`GroundArea.tab`提供设计尺寸。
3. 社区加载`maps/<地图资源名>/<地图资源名>.land`，私宅加载同目录`.pland`。
4. `.land`包含`LandIndex`、`X1/Y1`～`X4/Y4`、`Z`、`ROTATION`及默认房屋/SDK字段；`.pland`另有`SubLandIndex`，0表示完整范围、1～7表示分区。
5. 实际加载路径分别为`KHomelandMapInfo::LoadLandIndexConfig`和`LoadPrivateLandIndexConfig`，逐列读取四角并交给`KLandIndexConfig::AddLand`。

平面坐标按**64逻辑单位/米**换算，通过设计边长、社区标称面积和私宅分区交叉核对。108块社区地的多边形面积与表中面积最大差约0.8614平方米，来自旋转四角的整数坐标舍入；界面展示表中标称面积，绘图保留实际四角，保留坐标舍入形成的面积差异。

`.land/.pland`的原始Z与ROTATION保留在数据中供继续研究。平面图使用四角坐标中的方向，不将原始Z解释为米制高度，也不重复应用ROTATION。地形与周边场景不在平面图显示范围内。

## 与3D布置及蓝图的关系

“3D家园布置”中的“选择户型 / 地块布局”打开总览；选择后点“用于布置”，画布显示真实比例的边界、网格以及可用的私宅分区标记。“俯视地块”可重新查看整个范围。“不设范围”恢复自由布置。

编辑器以所选地块包围盒中心作为平面参考原点。切换范围不会搬动、缩放或删除已有家具。选择随`.homeland.json`工程保存，也参与撤销和重做；旧工程没有该字段时仍然可以读取。

表中平面X/Y分别对应编辑器X/Z。二维总览与3D俯视采用同一观察方向，第二平面轴向屏幕下方递增；该方向不代表游戏地图的地理北向。

### 边界限制

选定地块后，添加、复制、移动、旋转、缩放、导入与导出均检查水平边界。检查使用家具模型包围框的8个角，应用缩放和四元数旋转后投影到地面；家具中心在范围内并不足够，整个投影都必须位于地块四边形内部。

拖动平移时，计算能容纳完整家具的锚点区域，再停在离指针最近的合法位置。旋转或缩放将越界时保持上一个合法状态。数字输入越界则拒绝本次修改。切换后现有家具超出目标范围时，会保留原地块并明确提示，不自动挪动或删除家具。

导入局部蓝图时沿用当前地块检查；导入工程时使用工程自己的地块选择。最终导出核心也检查边界，无法仅通过改网页输入绕过。未设置地块时保持自由布置；“不设范围”是主动关闭这项约束。

这些是水平范围检查；地形起伏、家具碰撞、地下/高空规则与地块解锁状态仍由游戏核对。没有从未经解释的原始Z字段推测一个统一建造高度。

地下室资源和局部高度接口见[地下室组件与地形洞口](23-basement-and-terrain.md)。地块边界检查允许资源配置范围内的负Y值，不将地面参考平面视为不可穿越的碰撞体。

编码后的文件再次回读并检查边界。坐标使用float32保存，比较允许0.0001米的数值容差，避免合法贴边位置因浮点舍入无法重新导入；这不是额外可建造空间。

**导出类型取决于布置内容与导出模式。** 不含地下室且未合并原整屋时导出局部组件；含地下室或合并原整屋时导出整屋蓝图。私宅分区仅限定编辑区域，其整屋根平面仍为212×216米，两轴半尺寸为10600、10800渲染单位。分区中心相对完整宅园中心的偏移会应用到地面家具和地下室节点，地下家具保持相对地板的局部变换。

例如，第二区域的编辑原点在完整宅园坐标中为(-78,-32)米。区域内(-12,-12)米的地下室导出为(-90,-44)米。不能把56×72米的分区尺寸写成整屋根平面；较小的整屋文件会进入游戏的搬入流程，并按整个放置矩形检查可建区域。

工程文件保存原分区。读取整屋蓝图时，若当前已选范围对应同一整屋尺寸，则换算回当前分区坐标；否则显示文件实际范围，不推断社区、地址或外观。合并导出保留原整屋文件的内容，单独选择分区不会改变整屋导入的覆盖范围。

网页执行所选范围的水平边界检查；地块权限、库存、容量、解锁状态和保存检查仍由游戏执行。

## 维护与二次开发

`data/land_catalog.json`保存七档设计规格、五个社区108块地和私宅7区的数值资料，并记录每份输入的SHA256。可按数值目录复现地块布局与边界检查。

```sh
python tools/build_land_catalog.py --assets ./client-assets --output data/land_catalog.json
pnpm catalog
pnpm test
```

核心模块`packages/core/src/land.ts`负责选择、参考原点及网格裁剪，不依赖Three.js。`land-panel.ts`用SVG显示总览，`scene-viewer.ts`显示平面范围。新增地图应补齐地图身份、标称面积和四角数据，先验证面积、编号唯一性及分区覆盖，再加入选择器。
