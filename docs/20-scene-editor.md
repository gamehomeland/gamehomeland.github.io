# 家具布置、地下室挂接与蓝图导出

## 支持范围

网页“3D家园布置”包含单件预览和在线布置两个模式。内置库有38份GLB，36件普通Mesh家具已建立可导出的资源绑定。西苑亭灯样本仅包含Prefab内部网格，挂接基座样本仅为裸网格，完整装配未作为编辑家具开放；它们仍可单件查看。

可执行：添加、点击选取、移动、旋转、允许的等比/分轴缩放、样式编号、复制、删除、落地、聚焦/俯视、撤销重做、保存/打开工程、导出蓝图和完整包、重新读取本编辑器蓝图。

画布编辑仅接受已支持的整屋结构、绑定资源及地下室地板子家具，不读取任意复杂Prefab或其他挂接子树。合并底图采用独立的结构遍历与原字节保留路径，可保留未加入网页模型库的已有家具；该路径不提供这些原对象的可视编辑。

## 1. GLB与游戏家具的资源绑定

地块布局选择提供七档尺寸、五社区108块地与私宅7区。范围随工程保存、参与撤销，但不写入局部蓝图、不改变家具位置。边界数据和坐标转换见[地块规格与布局](22-land-layouts.md)。

`data/editor_catalog.json`每项保存：家具类型/家具ID、表现资源ID、默认Detail和允许样式、缩放维数与范围、自由旋转标记、位置高度范围、实际模型包围盒、Mesh哈希与GLB哈希。

目录由 `tools/build_editor_catalog.py`从家具索引与带明确 `resourceId` 的模型清单生成。必须唯一匹配普通Mesh家具；资源身份由编号、类型及哈希确认。浏览器加入模型时校验GLB SHA256，只有目录内绑定模型进入编辑场景；其他自有GLB仍能单件预览。

```sh
python tools/build_editor_catalog.py --index docs/furniture-index.json --manifest preview-manifest.json --output data/editor_catalog.json
pnpm catalog
```

GLB清单和模型放在同一目录。清单格式在常规模型预览字段之外增加 `resourceId`。`scripts/build-catalog.mjs`生成编辑器可用的TypeScript目录，应用运行时不读取整个9302行家具索引。

空缩放字段不代表无限缩放。所核对游戏操作层只在 `szScaleRange` 或轴范围存在时开放缩放；编辑器对空范围固定为1。`bFreelyRotate`不开放时只允许水平Y轴旋转。非等比资源读取三轴各自范围，必须分别保存各轴缩放分量。

## 2. 工程数据与显示分离

工程JSON格式为 `homeland-layout`，版本1。每件保存稳定编辑ID、资源key、Detail、米制世界位置XYZ、四元数XYZW和三轴缩放；地下家具额外保存`basementId`。工程JSON不内嵌GLB；蓝图按游戏节点结构序列化。

```text
SceneDocument → validateScene → SceneHistory
       │              │
       ├─ SceneViewer：GLB实例、选取、操作轴、观察相机
       ├─ 工程JSON：再次编辑和恢复
       └─ exportSceneBlueprint：游戏节点、变换、摘要、回读
```

稳定编辑ID用来识别撤销记录中的对象；导出时另外分配连续文件实例ID。资源身份、显示实例序号和游戏库存编号不能相互替代。

## 3. 移动、旋转和缩放

画布使用Three.js、OrbitControls和TransformControls。点击几何后沿父对象找到编辑ID，操作轴作用于该家具的显示根。位置使用米，旋转使用单位四元数；表单以角度输入旋转，工程保存单位四元数。

一次操作轴拖动在结束时提交一条历史。数字输入离开字段后提交，仅修改被编辑的分量；未改动字段不因显示小数位而丢失原精度。固定比例、自由旋转和高度范围同时在界面及核心验证，直接修改工程JSON也不能绕过。

吸附值是编辑器操作步长：移动0.1米、旋转15度、缩放0.05，不是游戏摆放精度上限。落地按当前旋转/缩放后的模型包围盒最低点计算。新增家具按已有家具的旋转包围盒寻找空位；自动放置仅用于初始布局；手动操作仍允许家具重叠。

每个模型模板缓存一次，重复家具共享几何与材质，通过独立显示根保存位置。未提供模型时使用绑定目录的尺寸框，资源身份和工程变换仍存在；加载模型后替换显示，不改工程数据。

## 4. 撤销、暂存和文件

历史保留最多50个完整工程快照。添加、删除、复制、改名、清空和变换都可撤销；撤销后进行新修改会清除旧重做分支。快捷键为Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z或Ctrl+Y；输入文字时不抢占系统编辑快捷键。

当前标签页使用sessionStorage暂存有效工程，刷新可恢复。不同标签页的草稿互不覆盖。关闭页面前应保存 `.homeland.json` 文件，作为可携带的工程。存储不可用时界面提示保存工程，导出功能继续可用。

完整包包括：真实 `.blueprintx`、工程JSON、按家具类型/ID/样式汇总的清单、使用说明。布置中的重复家具会累加数量，不按模型文件去重后少算库存。

合并完整包另附“原始整屋.blueprintx”。工程和清单只记录新增部分，后续编辑继续使用原始整屋作为底图，避免重复追加。底图仅保存在当前页面内存和导出包中，不写入会话草稿；刷新后需要重新选择文件。

## 5. 蓝图文件写入

无地下室时，本编辑器输出局部V7文件：`global=0`，根为type8 Holder，表现资源为 `0xffffffff`，根变换为单位变换。根下直接保存每件普通type0 Model，保持资源ID、Detail和SRT。

普通模型头为17字节，等比SRT为32字节，因此节点49字节。明确配置非等比的资源写40字节SRT，节点57字节。文件本身不自描述缩放维数，读取时通过目录的非等比资源集合选择，布局选择必须依据资源配置。

模型未挂接子家具时写 `childCount=0`。游戏加载路径先按资源创建模型和默认挂接容器，未使用的挂面无需写入文件。对应加载函数为 `KRLHomelandBuilder::_LoadBlueprintNode`，Holder和普通Model分别创建，再按保存的子树推进。复杂挂接尚未纳入本编辑器写回范围。

米制位置乘100进入文件坐标；四元数不改成欧拉角写入；等比资源写单值，非等比资源写sx/sy/sz。完成后计算格式要求的MD5变体摘要，重新解析整个文件并逐件比较资源、样式、位置、旋转和缩放。校验未通过不提供成功下载。

## 6. 工程与蓝图重新导入

含地下室时切换为整屋V7文件，根为type5平面，地下室以type9节点保存。新建整屋写入空绘制块，合并导出保留原文件的地表/植被块。完整资源和连接规则见[地下室组件](23-basement-and-terrain.md)。导入前应保存原有家园布置；地下室的游戏导入与保存重载需要单独验收。

`.homeland.json`直接恢复工程数据。`.blueprintx`则先核验摘要、版本、根结构和资源缩放规则，再建立家具记录。导入只接受支持范围内的结构；重复实例、未知资源、非法样式、无效四元数、范围越界和未支持子树都会拒绝。

重新导入会保留从文件读回的实际float32数值。模型可在工程恢复后继续加载；模型缺失或加载失败时，对象数据仍然保留。

## 7. 验证与边界

### 整屋合并

`mergeWholeBlueprint(base, addition)`接收原整屋与新增场景字节。先验证摘要、场景范围、节点边界和资源缩放布局，追加新增节点，再执行地下室连通更新。地表、植被与未受影响节点按原字节保留；相接房间及挂面变换按连通结果更新。新增实例编号从原文件的下一编号起分配，根子节点计数、编号边界、包围盒及摘要随之更新。原文件和传入缓冲区均不修改。

同规格的新增与原地下室可横向或上下连通。`blueprint-connect.ts`同步调整相接双方的掩码、模型形态和旋转，根据挂面标签、世界位置及法线匹配保留面，再重算子挂件的局部SRT。已移除表面的挂件转挂到连通区域内的可用地板；家具的世界变换、实例编号、业务字段和后续子树保留。

`blueprint-structure.ts`负责只读结构遍历，`blueprint-transform.ts`计算坐标和保留检查。合并结束后逐实例核对家具世界矩阵，并比较非SRT业务字段。未知节点、无法解释的挂面、重叠、错位连接和4米/8米直接连接会返回明确提示；原文件不修改。

新增深层单元依赖原房间时，工程保存`basementMergeOnly: true`。`exportSceneBlueprint(document, {forMerge: true})`生成供合并使用的新增片段，随后必须调用`mergeWholeBlueprint`得到最终整屋文件；片段不能作为独立家园使用。新建整屋模式仍要求新增地下室自行连到地表。

网页从实际合并字节读取原房间与原家具的只读预览。绿色扩建格按相同规格、工作层、已有单元和所选边界计算；画布预览与下载使用相同的连通结果。模型库未包含的原家具显示位置标记，其蓝图数据完整保留。

私宅七区的整屋根范围一致，分区坐标换算见[地块规格](22-land-layouts.md)。4米新增单元合并到原有8米地下室，以及合并到154个原对象的两组文件均有游戏内导入确认。其他场景、保存重载和通行仍需按对应布置验收。

验证包括纯核心的等比/非等比格式约定、资源约束、重复家具清单、工程与完整包一致性、撤销恢复和未知结构拒绝；浏览器实际进行了数值编辑、复制/删除/撤销/重做、下载文件和清空后重导入。

桌案、椅子、蜡烛、分轴缩放柱子的四件测试文件由独立Python检查器解析为5个节点（含Holder），摘要和80个字段读取通过。该样例有游戏内导入记录及相对位置一致的截图。该证据证明这组局部布置的导入链，不代表所有家具、复杂挂接、所有场景或保存后重载均已验收。

GLB内嵌源贴图与材质样式，网页按Detail切换；游戏按资源和Detail显示原家具。材质转换与照明差异见[家具贴图与材质](21-furniture-materials.md)。网页没有复现全部材质、动画、发光、环境光或库存规则；实际游戏中的容量、权限和保存检查仍由游戏负责。

编辑器的对象、三角形、工程字节和坐标范围保护值见 `SCENE_LIMITS`，是本工具的处理预算，不是游戏全局上限。
