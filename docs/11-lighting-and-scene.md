# 家园光照、天气与画面显示

本章说明材质、场景和显示之间的关系，供配色、三维预览及场景编辑器开发使用。图像配色使用固定中性显示基准；家具预览采用内嵌材质与中性照明，不包含完整游戏渲染器。

## 1. 材质到屏幕像素的处理流程

```text
家具资源、Detail 样式、模型与材质
       ↓
纹理取样、线性颜色、法线、粗糙度、反射、自发光、透明度
       ↓
适用的天气与材质处理
       ↓
直接光、环境反射、阴影与所选渲染路径
       ↓
透明混合、遮挡、距离淡出
       ↓
显示变换与后处理
       ↓
屏幕像素
```

上图是功能关系图，具体计算顺序以实际渲染分支为准。前向和延迟路径不能简单套用同一段函数。

`linearColor` 只是材质的线性反照率；它本身不是某天气、某视角下的最终 RGB。修改曝光可以改变屏幕观感，却没有增加一种新家具颜色。

## 2. 拼布材质类型

色卡中的拼布使用 `mtl_std_colorize.fx5` 和 `mtl_std.fx5`，定义为 `MATERIALID_STANDARD`。家具叫“拼布”不表示它自动使用着色器中的 `MATERIALID_CLOTH` 分支。

材质计算产生 `Albedo`、`Normal`、`Reflectivity`、`Fresnel`、`Roughness`、`Emissive`、`AO` 和 `Opacity`。基础纹理取样经过 2.2 次幂转换；染色材质还使用颜色参数与纹理掩码。具体反照率已整理在 `data/furniture_palette.json`。

色卡中的不透明拼布材质为双面，透明灰1为单面。透明层不仅要有正确颜色，还必须保证朝向和实际可见面正确。

### 预设染色与颜色参数

`FurnitureData.GetFurnColorInfos` 从 `Homeland_FurnitureColor.tab` 取可用索引，界面列出预设色，`HLBOp_SingleItemOp.Dye` 发送 `SET_DETAIL`。这是切换已有样式，不是给任意家具写入任意 RGB。

资料集包含790个有效可染色资源条目，与色卡的144个拼布资源编号交叉匹配，结果为 **0**。当前染色表未为这144个拼布资源提供额外Detail底色。

## 3. 光照、朝向与空间位置

`ForwardLightingEntrance.h5` 把材质法线转换成世界法线，再把材质属性、世界位置和屏幕位置交给光照函数。完整前向路径和简化前向路径分别调用 `ComputePBR_Light_Forward`、`ComputePBR_Light_Forward_Minimal`。

完整路径存在点光、方向光、聚光以及 DDGI 条件分支。公共参数包含光源颜色、强度、位置、范围和阴影信息；有这些入口不代表每个场景、每档画质都启用它们。

对于二次开发预览，至少要区分：

| 因素         | 对画面的影响                           | 需要记录的输入             |
| ------------ | -------------------------------------- | -------------------------- |
| 法线与朝向   | 同一拼布转成墙面、地面后，受光关系改变 | 家具旋转、表面法线         |
| 直接光       | 改变明暗、色温及高光方向               | 光方向、颜色、强度         |
| 粗糙度与反射 | 改变高光与环境反射观感                 | 对应材质参数               |
| 阴影         | 改变局部光照，不能按整图统一变暗       | 遮挡几何、阴影参数         |
| 环境反射     | 受场景位置及附近探针影响               | 探针位置、范围、强度与颜色 |
| 自发光       | 对最终光照结果增加贡献                 | 材质与渲染分支             |

墙面和地面不应永远套用一个固定亮度倍率；室内与室外也不适合简单写成两个常数。

## 4. 环境探针、GI 与阴影

`ShadingModel.h5` 的 `ComputeIBL_MultipleEnvProbe` 使用世界位置、相机方向、探针位置/半径及变换求取反射。`CommonParam.h` 的环境反射参数还分别提供强度、饱和度与旋转。`GIForwardCommon.h5` 定义世界探针覆盖与粗糙度等处理。

场景颜色还受到局部探针与遮挡关系影响。室内是否受到某个探针覆盖、周围几何如何遮挡，都可能影响结果。设计场的静态灯光数值保存在环境参数资料中；具体地图探针与完整运行时状态不属于离线重放能力。

阴影参数包含太阳光矩阵、阴影图层级与相机范围，也有其他光源的衰减数据。拼布可见性测试用于确定采样位置的最近可见家具，不模拟游戏阴影、GI或反射。

## 5. 天气与时辰切换

天气切换调用链：

```text
HLBView_WeatherSetting.OnCheckBoxCheck
  → HLBOp_Other.SwitchWeather(time, weather)
  → Table_GetHomelandEnvironment(time, weather)
  → Homeland_Weather.tab
  → 选择对应的环境预设
```

当前表中的 9 个组合：

| 时辰编号 | 时辰 | 天气1     | 天气2     | 天气3     |
| -------- | ---- | --------- | --------- | --------- |
| 1        | 中午 | 晴天_中午 | 雨天_中午 | 雪天_中午 |
| 2        | 早晨 | 晴天_早晨 | 雨天_早晨 | 雪天_早晨 |
| 3        | 黑夜 | 晴天_黑夜 | 雨天_黑夜 | 雪天_黑夜 |

**天气枚举按模块分别定义。**建造面板顶部的局部枚举名称与该表的雨雪顺序存在差异，实际查表以键和 `szEnvironment` 为准。动态天气 API 的 `eType` 和 Shader 的 `WeatherType` 又是各自独立的字段。

建造界面结束时，`HLBOp_Other.UnInitWeather` 重置环境与本地动态天气，并重新应用用户的时辰/氛围设置。预览时切过天气，不表示这项状态随本工具的局部拼布组件保存。

## 6. 雨雪材质处理分支

### 条件性雪覆盖

`ModelBasePixelShader.fx5` 在天气启用、非特殊光且对应天气类型的条件下调用 `RenderSnow`。函数首先计算表面法线与世界向上的点积，小于 **0.8** 时返回原反照率；通过条件后还会使用俯视深度、雪覆盖掩码及噪声。

该分支对表面朝向与上方遮挡分别进行条件判断。雪覆盖计算依赖表面方向、遮挡及掩码。这些结论只适用于所核对分支。

### 雨处理分支的有效性

虽然主路径调用 `GetWetnessMask`，但所核对实现的计算主体已注释，实际返回 `(1, 1)`；所检查的 `RenderRain` 直接返回输入颜色。该分支不提供可据此确认的湿润、变暗或粗糙度变化。

另一方面，`DynamicWeather_Base` 的数据接口确实包含雨强、粗糙度、底色变暗、流动法线等参数，并传给 `KG3DEngine.SetDynamicWeatherParam`。它们可能用于其他分支；实现这些效果需要对应的有效调用点与材质，不能仅凭参数名称补算法。

## 7. 透明度影响因素

灰1纹理 alpha 为 `128/255`，其基础取样不透明度为 `(128/255)^2.2`。主像素路径还会把材质不透明度乘以模型 alpha，并可根据相机远平面、淡出起点比例和指数继续衰减。

所以基础 alpha、实际画面透明度和视距不是同一个概念。透明叠层还涉及双面状态、深度、排序和照明，不能只按图像编辑器的几层 PNG 混合来保证游戏效果。

本工具普通布局最多使用六件拼布组成一格配色；颜色在线性空间混合后统一显示。默认微缩底层使用不透明单层。试验扩色在其前方增加独立透明层，并验证透明覆盖，见扩展材质章节。

## 8. 显示变换与后处理

在所描述的模型像素入口中，局部 `Tonemap(..., 0.5)` 只在 `bEnableRenderLevelLow && bEnableForwardMinimal` 条件下执行。`CommonParam.h` 的该函数保留原 alpha，对 RGB 做曝光与曲线映射。

网页色卡以该函数构造固定中性基准，不能把它当成所有渲染档位的完整显示流程，已映射的RGB应避免重复gamma转换。

`Filter_Base` 提供曝光、增益、对比度、饱和度、柔光、暗角、颗粒、色散和高光等后处理入口。时辰与氛围还会按地图恢复用户设置。`SetUserEnvPreset` 中存在新日夜循环全效果条件下拒绝切换预设的分支，不能承诺任何地图、画质都允许同一种天气控制方式。

## 9. 预览精度扩展方案

建议将预览数据分为三层：

1. **材质层**：资源编号、Detail、线性反照率、法线、粗糙度、反射、自发光、基础 alpha 与双面状态。
2. **场景层**：朝向、光源、环境探针、天气覆盖、阴影和相机。
3. **显示层**：渲染分支、曝光、显示曲线与滤镜。

可以先实现一个固定方向光和环境光的参考预览，再分别加入真实探针和阴影。每加一项，都用同一份蓝图核对，避免把模型差异误当成色卡差异。

建议校准记录包含：家具编号与规格、层次与间距、位置、朝向、观察距离、天气时辰、画质档位、滤镜、曝光和取样区域。用黑白灰、红绿蓝、肤色和渐变测试，取样时排除边缘、基座和高光，不把不同条件的截图混成一张表。

**GPU可加速候选计算和三维渲染；光照还原仍依赖完整的场景数据。**当前核心的确定性 CPU 导出与文件回读可以继续保留；二次开发预览应明确所用场景和模型。

## 10. 复核与扩展入口

`docs/scene-reference.json` 包含天气组合、设计地块预设、染色表交叉核对和资源哈希。`tools/scene-resource-paths.txt` 列出所需资源；原始游戏代码、模型、纹理不进入源码包。

使用现有只读资源读取器按该清单提取到独立目录，然后运行：

```sh
python tools/build_scene_reference.py --assets ./scene-assets --output ./scene-reference.json
```

生成器会核对关键函数是否仍处于本章描述的状态。规则变化时明确报错，需要先复核再更新文字。它不会启动游戏或调用这些渲染命令。

项目不包含完整延迟与后处理渲染器、地图运行时光源/探针重放或全画质雨雪模拟。环境资料说明结构与入口，游戏内光照校准不属于自动验证范围。

## 11. 设计场照明数值

实际资源索引链为 `filepath.ini → scene_data.krl.txt → 地图jsonmap → 画质目录及环境预设`。场景名称与界面字符串表交叉核对：编号0为“空旷原野”，编号1为“山水画卷”。

两场景 × 三条画质路径（HD、BD、Low）× 默认环境和九个天气时辰组合，共 **60份**配置，已整理为 `environment-reference.json`。只保留数值、路径及哈希，不包含原始地图或纹理。每份记录分别保留太阳、月光、光源选择和日夜循环标记。

例如“空旷原野”的晴天中午：

| 路径 | sun diffuseIntensity | sun ambientColor RGB      | enableDayNightCycle |
| ---- | -------------------- | ------------------------- | ------------------- |
| HD   | 4.0                  | 0.5、0.5、0.5             | 1                   |
| BD   | 4.0                  | 0.5、0.5、0.5             | 0                   |
| Low  | 3.5                  | 0.12134、0.15000、0.14905 | 1                   |

它们的静态太阳方向均约 `(-0.233257, 0.731354, -0.640869)`。按 `asin(y / length)` 得到仰角约47°；按 `atan2(-x, -z)` 得到约20°。后一个角是本报告的坐标约定，不能未经坐标核对就称为地理北向。

HD晴天早晨的方向为 `(0.953500, 0.258819, -0.154433)`、太阳漫反射强度3.0；同一路径黑夜配置的 `lightSource` 改为1。**夜间文件仍保留sunlight字段，不表示夜间继续使用它当主光源。**Low目录的若干不同文件也会保存相同的静态值，时刻或渲染逻辑可能继续覆盖它们。

因此，二次开发者应先实现正确的场景/画质/光源选择和时间处理，再使用这些参数。单一太阳方向和强度不足以替代场景运行时的光源选择与环境更新。

```sh
python tools/build_environment_reference.py --assets ./scene-assets --output docs/environment-reference.json
```

此生成器只整理真实配置的数值，不模拟运行中的天空、探针、柔光与阴影。网页使用中性显示基准，静态环境参数不构成完整的3D光照实现。
