# 第 7 版蓝图格式

依据客户端 `KRLHomelandBuilder` 的加载、保存、节点创建和校验分支核对。本工程实现拼布、绑定家具及地下室地板挂接所需的节点子集。遇到不支持的节点或数据块时停止读取，并保留原始输入。

## 文件层

文件头为 `uint8 global`、`uint32 version`，使用小端序。局部组件 `global=0`，节点从第 5 字节开始。全局场景还有可变长度场景头：`codec.ts` 的可编辑输入限于节点从第 222 字节开始的无地表/植被绘制子集；整屋合并器使用 `blueprint-structure.ts` 按字段长度读取，并保留原有地表与植被块。不得将 222 作为所有整屋文件的固定偏移。

末尾 16 字节是校验：对前面全部字节求 MD5，结果循环左移一个字节，再逐字节 XOR `0x33`。客户端 RVA `0x89E9F0` 可见该循环和异或；它用于文件完整性，不是加密。当前加载函数有一处比较 15 字节的分支，本工程按完整 16 字节验证和生成，保持更严格的完整性检查。

## 节点类型

客户端类型表：0 Model、1 BrushModel、2 SubGroupModel、3 GroupModel、4 LightModel、5 PlaneContainer、6 SlotContainer、7 MultiPlaneContainer、8 HolderModel、9 CascadeBrushModel。

`codec.ts` 支持0、3、8、5～7及地下室使用的type9级联笔刷。图片转换仅使用拼布子集；家具编辑器按资源目录校验Model，地下室按专用目录校验CascadeBrush。灯光、普通笔刷和子组不作为可编辑输入。整屋合并器可按已知布局遍历并保留这些节点，不提供任意节点编辑或灯光参数修改。

### 普通对象头：0、3、8

| 相对节点起点 | 类型        | 含义                                                                            |
| ------------ | ----------- | ------------------------------------------------------------------------------- |
| 0            | uint8       | 节点类型                                                                        |
| 1            | uint32      | 标记；当前客户端保存路径只写最低位的一个状态，保留完整字段                      |
| 5            | uint32      | 实例编号，对象树中唯一                                                          |
| 9            | uint32      | 资源编号；Holder 可使用 `0xFFFFFFFF`                                            |
| 13           | uint8       | 内建子节点标记；依据 `_Combine3DNodeSDKObject` 递归创建预制体子节点的调用链解释 |
| 14           | uint8       | Detail 样式编号，已由 `_SetDetail` 与序列化交叉确认                             |
| 15           | uint16      | 直接子节点数量                                                                  |
| 17           | float32 × 8 | 等比缩放、四元数 XYZW、平移 XYZ                                                 |

默认模型头共 49 字节。客户端对允许非等比缩放的资源会读写三个缩放分量；图像转换器所用拼布均为已确认的等比规格，家具编辑器仅对资源目录中明确配置非等比的型号开放分轴缩放。

### 挂面/挂点头：5、6、7

`uint8 type + uint16 index + uint16 child_count`。有子节点时继续写 8 个 float32 变换，没有子节点时省略变换。`index` 对应父资源中挂面或挂点的顺序，必须从资源定义读取。

当前拼布的 `.Mesh.jsonAP` 仅含平面挂点；原生 `_AttachAnchor` 会按资源定义创建容器。144 个拼布规格的顶部挂点索引和偏移均由资源重新生成。

## 坐标与层级

四元数按 XYZW 保存。本工具生成的拼布组件，其子节点平移及挂点数据已经包含导出时所需的尺度，回读时不再对整条挂接链重复累乘缩放。这是当前导出器的变换约定，不能直接推广到任意非等比家具。检查器提供的是文件变换合成结果，实际导入时还存在编辑器放置朝向。

普通导出及微缩导出分别应用组件朝向补偿，并通过回读检查最终家具的目标平面。预览方向与蓝图家具方向分开验证。

## 读写的执行顺序

保存使用前序遍历：写父节点的头与变换，然后按顺序写各个子树。读取先建立节点，再读取声明数量的子节点。子节点声明与实际内容必须一致，否则后续字段偏移会错位。没有通用的“每节点长度”供解析器跳过未知类型；灯光自身有长度字段，但不能套用给其他节点。

`_StartLoadBlueprint`、`_LoadBlueprint` 与 `_LoadBlueprintNode` 将文件检查、场景加载和递归节点创建分开。资源是否存在、节点类型如何构造和变换如何修正，也不全由文件校验值决定。校验正确不表示资源或家具库存合法。

例如一个只有普通 Holder 的局部文件至少需要：5 字节文件头、49 字节节点、16 字节校验，共 70 字节。若增加一个非空挂面，就还要加上挂面头、32 字节变换和子树。该最小结构可用于校验解析器偏移。

## 完整性校验伪代码

```text
digest = MD5(payload)
for i in 0..15:
    suffix[i] = digest[(i + 1) mod 16] XOR 0x33
file = payload || suffix
```

改变 Detail、节点顺序、任意 float32 字节后都必须重算尾部。该校验没有密钥，不能用来证明文件来自谁，也不提供防伪能力。

## 边界

- 文件长度、节点总数和最大深度有独立上限；禁止非有限浮点数、未知节点和未消费尾字节。
- 子节点计数的存储上限为 uint16，并非当前已证明的游戏运行容量。
- 字节可往返、坐标可回读不等于客户端已导入；实际放置、移动、保存、重载分开验收。

全部节点、全局地表/植被块和逐字段偏移见[蓝图字段字典](13-blueprint-field-reference.md)。研究用只读检查器为 `tools/inspect_blueprint.py`，它的结构覆盖范围与当前图片转换核心不同。
