# 地下室组件、地形洞口与高度坐标

## 功能定义

家园地下室通过专用家具资源、级联笔刷及地形洞口模型共同实现。地下室轮廓、内部组件与地面开口分别由资源和渲染路径处理。普通家具的负Y坐标仅表示向参考平面下方移动，不会自动创建地形洞口。

官方资料曾列出地下室专用组件，见[“奉天证道”资料片介绍](https://jx3.xoyo.com/show-2458-4175-1.html)。本章的资源编号、参数和文件结构以本机资源表与原生加载路径的交叉核对为依据。

## 资源目录

家具信息表中有6项地下室家具，均通过`ID_Brush`关联到`type=2`的级联笔刷。普通模型资源表`ID_Model`不用于这些条目的几何关联。

| 家具            | 家具ID | 笔刷ID | extent | top | bottom |
| --------------- | ------ | ------ | ------ | --- | ------ |
| 地下室·木质·4米 | 2040   | 74     | 400    | 0   | -400   |
| 地下室·沧州石   | 2149   | 82     | 400    | 0   | -400   |
| 地下室·雪浪石   | 2150   | 83     | 400    | 0   | -400   |
| 地下室·石质     | 2151   | 84     | 400    | 0   | -400   |
| 地下室·木质·8米 | 5466   | 113    | 800    | 0   | -800   |
| 地下室·石质·8米 | 5863   | 114    | 800    | 0   | -800   |

表中为原始资源参数。400和800分别与4米、8米规格对应；`top/bottom`记录该笔刷配置的上下范围，不作为整个家园的地下深度上限。

这些条目的标签包含`H_Pool;Basement`。另有笔刷79使用`BasementAnti`标签，与木质4米资源共用路径及家具ID2040，其`top=bottom=0`。原生删除分支将79映射为74查找对应单元；回填通过删除已有级联对象并重算相邻掩码完成。本编辑器不把79作为可摆放家具导出。

## 地形洞口加载路径

原生`CascadeBrush::SetBrushID`校验配置类型为`BrushType_Cascade`，对应表中的`type=2`。`KRLHomelandBuilder::_Create3DBrushModel`在满足笔刷类型及掩码条件后，执行以下流程：

```text
笔刷资源前缀
  → GetBrushTerrainHoleMesh
  → <资源前缀>_TerrainHole.mesh
  → Model_CreateCommonModel
  → Model_SetFlags(eKG3DSNMF_TerrainHoleModel)
  → Node_AddModel
```

六种资源分别对应一个`TerrainHole`文件，其中部分文件的内容相同。该流程为地形洞口建立独立渲染对象，不以普通家具坐标替代洞口数据。洞口标志在所核对调用中为4；不得据此推定其他模型标志或掩码字段的含义。

6个洞口Mesh均使用布局标记`0xe4000000`。专用工具`tools/inspect_terrain_hole.py`读取已核对的位置流和三角形索引：位置流由两组边界float3和uint16三元组构成，量化除数为65400，最低位参与符号恢复。4米洞口的水平范围为[-2,2]米，8米为[-4,4]米；垂直范围分别约-0.3～0米和-0.6～0米。洞口模型的厚度不是房间深度。

该工具只解析此洞口子集的位置和索引，不将`0xe4000000`视为通用Mesh支持。网页按核对后的矩形轮廓裁切地面，并载入六种资源各24个原生Mesh变体。颜色、法线及金属/粗糙度贴图按材质定义转换为PBR；地形碰撞、天气和游戏光照不由GLB提供。模型未载入时保留明确标注的结构占位。

## 蓝图节点与编辑限制

级联笔刷使用蓝图节点类型9（`CascadeBrushModel`），固定部分为44字节，不含子树。主要字段为：

| 字段                   | 类型    |
| ---------------------- | ------- |
| 节点类型               | u8      |
| 实例编号               | u32     |
| 笔刷资源编号           | u16     |
| 邻接或显示掩码原值     | u16     |
| 兼容保留字段           | u8      |
| 子节点数量             | u16     |
| 等比缩放、四元数与平移 | f32 × 8 |

`_SaveCascadeBrushModel`与核心编码器及独立字段检查器采用同一字段布局。构造函数将对象+472处的值初始化为1，保存时写其低字节；本编辑器写1。两条已核对加载路径跳过该字节，历史业务名称仍未命名。

### 邻接掩码与资源变体

| 位值 | 方向或用途 |
| ---- | ---------- |
| 1    | +Z相邻单元 |
| 2    | +X相邻单元 |
| 4    | -Z相邻单元 |
| 8    | -X相邻单元 |
| 16   | -Y相邻单元 |
| 32   | +Y相邻单元 |
| 64   | 地表洞口层 |

原生邻接检测使用同一父平面、同笔刷类型和extent的资源组。不同材质的同规格单元可连接；4米和8米单元不归为同组。方向位表示相应面与邻居连通。地表层根据`abs(localY)<halfExtent`设置64位。

资源选择先将地表层的上方面视作开放，再对六方向取反得到需保留的面，按水平旋转归一到24种变体A～X；文件名为`<前缀>_<字母>_hd.mesh`。原生`CreateBrushModel`将归一化四元数设置到级联对象，保存时作为该对象的SRT写入。导出必须写入此旋转；子挂面的变换相对级联节点，不能把父旋转再次乘入子挂面。实现见`basementMasks`、`basementVariant`、`basementRotation`。

Lua操作层通过`FurnitureData.IsAutoBottomBrush`及`Homeland_GetModelIDsForBasement`识别地下室资源。已确认的界面行为包括：

- 地下室框选由独立开关控制，默认关闭。
- 包含地下室的选择集具有专用分组限制。
- 局部蓝图导出路径会检查选择集中是否包含地下室，并追加对应提示。

这些行为不能直接复用普通Mesh家具的选择、分组和导出规则。

## 局部高度与水平边界

高度面板读取家具的`szHeightLimit`，并调用`SetObjLocalPos(HOMELAND_SET_OBJ_LOCAL_POS_TYPE.Y, value)`。该接口设置对象的局部Y坐标；父节点、挂面和组件整体变换可能继续影响最终世界高度。

当前绑定的36件普通家具，其资料范围为-400～800坐标单位，换算为-4～8米。地面家具按根平面校验Y值，地下室家具按所绑定地板挂面的局部Y校验。这是已绑定资源的局部输入范围，不是全游戏统一的地下室深度或建造高度限制。

地块边界约束检查家具旋转、缩放后的水平投影，未将Y限制为非负值。配置允许的负高度可以编辑并写入局部蓝图；该操作不生成地下室洞口，也不重建地形碰撞。

## 编辑与导出流程

1. 在“选择户型 / 地块布局”设置范围，打开“地下室挖掘”。
2. 选择4米或8米组件、材质和工作层，点击画布格点。也可通过“按坐标操作”输入单元中心。
3. 同规格相邻单元自动连通。深层单元必须经上下或水平邻接连到地表洞口；不允许生成悬空的孤立地下单元。
4. “回填”删除当前层指定单元。若回填会断开下层通道，操作被拒绝；撤销与重做覆盖地下室、家具及地块选择。
5. “当前层剖面”隐藏上层和当前层顶面，便于核对下层空间；关闭后恢复整个结构。剖面只影响预览，不修改导出文件。
6. 含地下室时导出整屋V7蓝图，根为type5 PlaneContainer，地面家具及type9地下室直接写在根下；地下室内家具写入其地板挂面的子树。不含地下室时导出局部Holder组件。

整屋头使用完整根平面的两轴半尺寸、对象包围盒及实例编号边界。私宅七个分区共用212×216米的根平面，分区编辑原点通过`landBlueprintFrame`换算。地下室的导出平移为`[gridX*size+offsetX, -level*size, gridZ*size+offsetZ] * 100`。缩放为1，旋转采用连通形态对应的四元数。分区换算后允许四分之一格坐标，新增连铺保持同规格格点偏移。

导出保留模型定义中的全部PlaneContainer索引。空挂面只写5字节头；承载家具的地板写入局部SRT和家具子树。原生单单元样本含6个空挂面，不能将固定的“一个地板”当成完整挂面结构。旧版省略空挂面的文件仍可读取。

全新整屋采用空绘制层，但仍写入有效采样尺寸：地表为每米4格，植被为每米2格；地表缩放为`[根平面Z半长,5,根平面X半长]`，绕Y轴旋转90度。合并导出保留原文件的完整绘制块。掩码从新增布局计算，编码后回读验证资源、位置、层深和数量。

整屋导入替换整个家园。默认流程为载入游戏保存的整屋文件，将网页新增布置合并后导出。地表、植被和未受影响节点按原字节保留；相连房间同步更新掩码、旋转、挂面索引及必要的子挂件SRT。新增实例重新分配编号，根子节点数、总编号边界、包围盒和校验随之更新。全新整屋导出仅用于明确替换原布置的场景。

合并器按格式遍历原节点，不要求每件原家具已具备网页GLB。未知节点类型、未知缩放布局、重复编号、范围不符和校验失败均保留原文件并返回错误。模型、灯光的未命名业务参数保持原字节，不推断其含义。

| 能力           | 范围                                                                        |
| -------------- | --------------------------------------------------------------------------- |
| 地下室资源     | 6种组件：4米4种材质、8米2种材质                                             |
| 编辑           | 挖掘、回填、更换同规格材质、多层连铺、撤销重做、工程保存                    |
| 水平边界       | 整个单元的投影必须在所选地块内                                              |
| 预览           | 资源模型与贴图、地面裁切、连通形态与分层剖面                                |
| 导出           | type9节点、整屋根平面、家具清单、工程与说明ZIP                              |
| 本工具预算     | 最多512个地下室单元、底面深度32米；不代表游戏统一上限                       |
| 不同规格       | 可分区设置；不支持4米与8米重叠或直接连接                                    |

| 游戏验收       | 私宅单元合并与保留154个原对象的导入已确认；保存重载、其他场景和通行仍需验证 |

纯文件回读、独立解析器和网页几何测试分别验证字节、数值和可视结构，不能替代游戏内导入验收。地下深度32米是编辑器预算；原生射线放置路径可见3600坐标单位的检查，但不足以推导所有地图的统一地下深度上限。

## 模型与贴图转换

`tools/build_basement_models.py`读取六种笔刷前缀的A～X形态，共144个Mesh、144个jsonAP和144个材质包。`inspect_mesh.py`支持已核对的`0xe4000000`位置、法线、UVW和三角形流子集：

- 位置：两组float3边界、uint16三元组，按最低位恢复符号并除以65400。
- 法线：每轴一个字节，高位表示正方向，低7位表示幅度，除以127并归一化。
- UVW：float3最大绝对值和uint16三元组，解码为`(min(q/65400,1)-0.5)*2*max`。
- 三角形：保留顶点关联和材质槽，按GLTF正面约定统一调整绕序；不改变位置或UV。

每种材质的24个形态合成一个自包含GLB，PNG按内容哈希共享。随附六个网页模型包总计约2.1MiB；运行时每种材质只加载一次，重复地下室共享几何及贴图。形态A表示六面连通的空单元，按原生分支不绘制可见网格。分层通过裁切平面去除上方内容，不改变导出。

```sh
python tools/build_basement_models.py --assets ./extracted --reference docs/basement-reference.json --output ./models --catalog data/basement_models.json --report ./material-report.json
pnpm catalog
```

网页从 `models/basement/` 按需读取，桌面版从应用内相同目录读取。六个 GLB 与内嵌贴图均位于源码的 `assets/models/basement/`；单文件离线 HTML 可手动打开这些文件。文件需匹配目录 SHA-256 或已核对的同源别名，不允许引用外部纹理。接入及压缩步骤见[内置模型库](24-model-library.md)。

## 地下家具与挂面变换

每个变体的jsonAP含按顺序排列的挂面。只把标有`H_Floor`、旋转核对为水平的挂面用于地板绑定。144个变体中72个有地板；地板索引随形态不同，不能固定写1或4。

工程中的家具位置和旋转保持世界坐标，`basementId`记录所属单元。导出根据当前邻接重新选择模型与地板，再执行：

```text
地下室世界变换 × 地板局部变换 = 地板世界变换
地板世界变换的逆 × 家具世界变换 = 家具局部变换

type5 场景根
  ├─ 地面 Model
  └─ type9 地下室（含连通形态旋转）
       └─ type5 地板挂面（真实index、局部SRT）
            └─ Model家具（相对地板的位置、旋转和缩放）
```

继续连铺导致挂面编号或父旋转变化时，家具世界位置保持不变，导出时重算局部变换。地板上存在家具时，挖空或回填该承载单元会被拒绝；需先移动家具。家具可以跨同深度、同规格且水平相连的地板，但完整投影不能跨未挖掘区域或无底洞口。

界面提供三种入口：“新家具位置”设置添加目标；家具属性“所在区域”迁移已有家具；地下室工具“选择地板”通过点击实际模型选择地板。落地以真实地板高度和家具最低点计算。聚焦地下家具时按房间取景，避免相机落到墙体外侧。

## 与原房间连通及挂件保留

原生`UpdateBrushModel`先切换房间模型和挂面，再按标签、中心位置和法线匹配保留面，并将挂件从旧父坐标转换到新父坐标。编辑器采用同一坐标关系，但不会删除消失表面上的家具。

连通更新分为以下步骤：

1. 按完整侧面判断同规格邻接，同时更新原房间和新增房间的方向位。边角接触不视为通道；重叠与错位接缝拒绝导出。
2. 按新掩码选择模型形态和规范旋转。全部挂面数据来自对应形态的jsonAP，不能只保存地板或固定挂面编号。
3. 保留面按标签、世界中心与法线匹配；家具子树根变换为`新父世界矩阵的逆 × 旧父世界矩阵 × 原局部矩阵`。后续子树的局部字节不变。
4. 原墙面、天花或地板消失时，优先选择位于家具投影下方的可用地板；保持原高度与朝向。该操作改变顶层挂面归属，不扁平化家具内部挂接。
5. 逐实例核对编号、资源和非变换业务字段，并验证所有原家具的世界矩阵。任一检查失败即取消本次导出。

预览从合并后的实际文件读取房间形态和家具世界矩阵。原布置只读，新增单元可编辑；绿色提示格显示当前工作层的扩建候选。原图含48个地下室单元和155个家具/组对象的横向与向下连通样例已有游戏导入确认；独立解析确认原对象矩阵保持一致。该记录不代替所有资源、地图及容量组合的验收。
