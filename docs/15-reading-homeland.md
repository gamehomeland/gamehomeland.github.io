# 四格组件示例与蓝图结构

本章通过四格组件示例介绍家具资源、对象树、坐标与二进制字段。示例运行无需游戏环境；资源复核及游戏内验收需准备对应客户端。

## 1. 示例运行

在安装好项目依赖后执行：

```sh
pnpm example:structure
python tools/inspect_blueprint.py artifacts/structure-example/four-cells.blueprintx --output artifacts/structure-example/fields.json
```

[示例代码](../examples/inspect-component.ts) 输入四个颜色格，生成长边2米的墙面组件。它没有读取外部图片，也没有调用游戏。输出目录有：

| 文件                    | 内容                                             |
| ----------------------- | ------------------------------------------------ |
| `four-cells.blueprintx` | 蓝图二进制文件                                   |
| `preview.png`           | 导出结果的配色预览                               |
| `tree.json`             | 回读后的节点、材料和变换                         |
| `fields.json`           | Python检查器独立读取的字段路径、偏移、字节数与值 |

该示例在随附资料与算法下的输出为 **2×2格、4件拼布、1件基座、17个节点、478字节**。上述数值描述示例输出，不代表游戏容量上限。`gameImportVerified` 保持 `false`：程序已经检查文件，尚未代替玩家完成游戏内摆放与保存。

## 2. 术语与数据层次

| 词              | 定义                                 | 代码或数据入口                              |
| --------------- | ------------------------------------ | ------------------------------------------- |
| 家具            | 玩家需要准备的一件物品               | `MaterialItem.id/count`                     |
| 表现资源        | 这件物品采用哪种模型或预制体         | `Variant.representId`、节点的 `representId` |
| 实例            | 同一种型号在场景里摆出的某一件       | `BlueprintNode.instanceId`                  |
| Mesh / 网格     | 具体表面和几何形状                   | 资源指向的 Mesh；不会随源码分发             |
| Prefab / 预制体 | 资源本身预先组合好的对象             | `GroupModel`及其内建成员                    |
| Detail          | 型号已经提供的显示样式               | 节点的 `detail`，不是随意填写的RGB          |
| 挂面、挂点      | 某个模型允许子对象连接的位置与方向   | `PlaneContainer`等容器的 `index`            |
| 局部坐标        | 相对上级对象记录的位置与方向         | 节点的 `transform`                          |
| 世界坐标        | 把父子关系合成后，物体在场景中的位置 | 需要变换合成；不能只读某个 `px/py/pz`       |
| 组件            | 可以作为整体导入、摆放的一棵对象树   | 本工具的 `global=false` 输出                |
| 全局蓝图        | 带场景及地表、植被等信息的文件       | `global=true`及其可变场景块                 |
| 校验摘要        | 用来检查字节是否一致的尾部数据       | `checksum`，不能证明库存或摆放合法          |

例如基座家具编号6551，对应资源18230；其内建网格资源是18238。三个数字处于不同层次。资源18238属于基座内建网格，不单独计入购买清单。

## 3. 客户端模块职责

```text
玩家点击界面
    ↓
HLBView_*：显示面板、接收操作
    ↓
HLBOp_*：检查当前状态，组织操作，处理结果
    ↓ Homeland_SendMessage
原生建造器：建立对象、读取文件、执行变换、处理操作历史
    ↓ HOMELAND_CALL_RESULT 等结果事件
Lua刷新场景状态、分组、库存核算和界面
```

`Homeland_SendMessage`用于客户端内部操作通信。网页和导出库不调用该接口；它们独立生成文件，让玩家在游戏中导入。

| 问题                 | 主要入口                                                     | 需要的另一端                       |
| -------------------- | ------------------------------------------------------------ | ---------------------------------- |
| 文件类型判断         | `HLBOp_Blueprint.QueryIsGlobalBlueprint`                     | 原生文件检查及结果事件             |
| 同一型号对应哪件家具 | `FurnitureData.GetFurnTypeAndIDByModelID`                    | 家具表与资源索引                   |
| 操作前置条件         | `HLBOp_Check`                                                | 加载、移动、笔刷和查询状态         |
| 如何获得完整家具消耗 | `HLBOp_Amount.RequestConsumption/OnRequestConsumptionResult` | 分阶段返回的数据                   |
| 导入操作撤销         | `HLBOp_Step.StartOneStep/EndOneStep`                         | 原生操作记录                       |
| 最终能否保存         | `HLBOp_Check`、`HLBOp_Save`                                  | 玩家库存、地块、运行时与服务端结果 |

`HLB`是这些家园建造模块的命名部分，`Op`表示操作层，`View`表示界面层。分析应以调用关系、参数与返回值为主，变量名称仅作定位参考。具体追踪方法见[操作与排错](16-client-operations.md)。

## 4. 节点结构与家具数量

示例对象树的简化结构如下。每件拼布还保留资源声明的挂面；括号表示结构职责：

```text
Holder（组件根）
└─ 基座预制体（计1件家具）
   └─ 内建网格（属于基座，不另计家具）
      ├─ 空挂面
      └─ 已使用的挂面
         └─ 第1件拼布
            ├─ 空挂面
            └─ 已使用的挂面
               ├─ 第2件拼布（各自还带两个空挂面）
               ├─ 第3件拼布（各自还带两个空挂面）
               └─ 第4件拼布（各自还带两个空挂面）
```

对象数量为1个Holder、1个GroupModel、5个Model和10个PlaneContainer。Model包含1个基座内建网格和4个拼布实例。容器负责连接关系，不是可购买物品。

对象树层级与颜色叠层分别描述结构和显示关系。示例中的四块拼布在目标平面上相邻，子对象独立记录位置与旋转。树的深度、透明配方的层数、场景中的空间高度是三个不同的量。

## 5. 文件长度与字段偏移

该示例的普通对象均采用等比变换：

| 部分       | 计算                 | 字节数 |
| ---------- | -------------------- | ------ |
| 局部文件头 | 1字节标记＋4字节版本 | 5      |
| 普通对象   | 7个×49字节           | 343    |
| 空挂面     | 8个×5字节            | 40     |
| 非空挂面   | 2个×37字节           | 74     |
| 尾部摘要   | 16字节               | 16     |
| 合计       | 5＋343＋40＋74＋16   | 478    |

在 `fields.json` 中，`root.type` 位于绝对偏移5，`root.instanceId`位于10，`root.resourceId`位于14。字段字典中的普通对象偏移是**相对节点起点**：实例编号相对5，所以本例绝对位置是5＋5＝10。

子树大小可变，不能认为第二件家具总在某个固定文件偏移。每个节点先声明直接子节点数，再逐个读取完整子树。空挂面省略变换，非空挂面才有32字节变换，读取时需依据子节点计数选择对应布局。

完整定义见[字段字典](13-blueprint-field-reference.md)。等比与非等比、灯光、地表和植被都有不同长度规则，478字节示例仅覆盖其使用的节点组合。

## 6. 尺寸、方向与采样精度

四格组件示例总宽2米、横向2格，所以每格目标间距是1米。选用2米规格时，0.5倍缩放即可得到1米实体，不需要微缩遮挡。

高密度的8米图案可能具有小于最小拼布实体边长的目标格距。这时必须同时考虑实体大小、倾角、重叠及观察方向。增加网格只提高目标采样密度，不会自动增加家具的可用尺寸或颜色。

`transform`的八个数依次是：

```text
[scale, qx, qy, qz, qw, px, py, pz]
```

四元数表示旋转，不是四个角度；`[0,0,0,1]`表示单位旋转。文件中的平移是游戏坐标单位。对所核对拼布，100单位对应1米；基座内部的Y偏移1单位因此是0.01米。

图片转换器写出的挂接偏移已按其布局约定归一。`placedNodes`合成时累积旋转和平移，不再次对所有后代位置乘父缩放。二次开发者若改成一般场景编辑器，应先验证目标实现的变换约定，不能把这条导出器规则套给任意非等比模型。

## 7. 材质参数与显示结果

显示结果的分析链如下：

```text
家具资源与Detail → 材质和纹理 → 线性反照率与不透明度
              → 几何朝向、遮挡、光照、环境反射
              → 显示变换、曝光和滤镜 → 屏幕像素
```

- 资源决定有没有这种实际家具；每个配色项必须关联有效家具资源。
- 材质中的线性颜色不等于显示器上的颜色；混合应在所选模型的正确空间中进行。
- 家具预设染色、透明叠色、调节曝光是不同机制，不能互相代替。
- 墙面与地面法线不同，天气、阴影和反射也可能不同。
- 网页中性预览用于稳定比较配方，游戏实景校准需要固定时辰、天气、画质、相机和滤镜。

配方计算见[材质与颜色](02-rendering-and-color.md)，光照链和60份设计场配置见[光照与场景](11-lighting-and-scene.md)。场景配置给出静态参数，未包含完整运行时重放。
