# 解析覆盖、家具索引与在线3D扩展

## 功能范围

图片转换器生成局部拼布组件，回读文件后提供2D/3D预览。顶部“3D家园布置”提供单件查看和在线布置：38份内置模型样本中，36件普通Mesh家具已建立资源绑定，可选取、移动、旋转、按规则缩放、复制删除、撤销重做，并导出或重新导入支持范围内的蓝图。地下室支持原整屋只读预览与连通扩建；复杂Prefab、未知挂接及任意整屋编辑不在此范围，详见[编辑器实现](20-scene-editor.md)。

解析能力应区分四层：读出字节、理解字段、正确编辑并写回、游戏内保存重载通过。各层分别记录验证结果，模型显示不作为游戏内保存的验证依据。

## 1. 蓝图解析范围

| 数据                        | 应用核心（按功能校验）          | 只读检查器                               | 尚未覆盖                          |
| --------------------------- | ------------------------------- | ---------------------------------------- | --------------------------------- |
| V7局部头和摘要              | 读写与逐字节往返                | 读取校验                                 | 其他版本通用迁移                  |
| Model、GroupModel、Holder   | 按资源支持等比及非等比节点      | 依资源选择缩放维数                       | 任意资源的非等比编辑              |
| Plane、Slot、MultiPlane容器 | 支持已核对挂面                  | 读取空/非空容器                          | 所有家具挂接规则及游戏验收        |
| SubGroup                    | 不接受为转换输入                | 容器状态、UserData标签掩码               | 通用写回                          |
| Brush、CascadeBrush         | 图片不接受；编辑器支持6种地下室 | 读取结构及兼容保留字节                   | 其他笔刷、复杂挂接、游戏保存验收  |
| LightModel                  | 不接受为转换输入                | 路径、变换、184字节兼容参数              | 52字节未知区、完整枚举/单位及渲染 |
| 全局头                      | 读写已核对的空绘制子集          | 按字段读取                               | 任意整屋编辑                      |
| 地表                        | 拒绝带绘制数据的转换输入        | 资源/实例/缩放、块摘要，可选有界LZMA解压 | 真实非空样本覆盖、渲染及写回      |
| 植被                        | 拒绝带植被数据的转换输入        | 类型、缩放与格子原值                     | 每格第二字节语义及写回            |

检查器按资源表判断49/57等不同节点长度；节点长度由类型与资源配置确定。目录外资源可用 `--models ID_Model.txt` 提供规则。未知版本、未知节点、截断和无法解释的尾部均拒绝。具体偏移、已命名字段与未知区域见[字段字典](13-blueprint-field-reference.md)，机读证据见 `blueprint-semantics.json`。

表中“应用核心”指可编辑输入与新建导出。原整屋合并另使用结构遍历路径，可保留已知格式的地表、植被、灯光、笔刷、子组及原挂接树。连通时只更新受影响房间的形态和必要挂面变换；原家具按世界矩阵和非变换字段核对。保留原数据不表示这些内容都可在网页编辑。

## 2. 家具目录与资源身份

地下室属于级联笔刷资源，编辑器支持6种组件的挖掘、回填、邻接更新、原始模型贴图预览、地下家具挂接和整屋导出。普通家具的负高度放置不具备地形挖掘效果。相关资源、节点及洞口加载路径见[地下室组件与地形洞口](23-basement-and-terrain.md)。

`furniture-index.json`提供五张表的元数据，`furniture-coverage.json`保存统计、源文件SHA256和关联差异。这些大索引不参与网页日常加载。

| 资料           | 数量                                   | 说明                               |
| -------------- | -------------------------------------- | ---------------------------------- |
| 家具目录       | 9,302行                                | 含占位和测试标记，不等于全部可购买 |
| 分类           | 84行                                   | 保留三级分类                       |
| ID_Model       | 17,879行                               | 普通模型、预制体、动画、特效等资源 |
| ID_Brush       | 130行                                  | 普通笔刷及占位                     |
| ID_CustomBrush | 27行                                   | 20个植被、7个地表资源              |
| 正表现编号家具 | 9,301行                                | 按类型分派后全部能定位资源条目     |
| 关联分支       | 9,162普通模型、112普通笔刷、27特殊笔刷 | 三张资源表分别保留编号空间         |
| 双向身份一致   | 9,284行                                | 家具类型与家具ID均一致             |
| 资源身份差异   | 17行                                   | 保留目录与资源反向ID，不能强行合并 |

单查ID_Model会遗漏138行，也会把ID碰巧相同的一条笔刷误归入普通模型。索引根据家具类型和笔刷模式分派，输出 `resourceTable/resourceId/resourceFound/identityMatched`。17条连铺/笔刷家具虽有资源，但反向FurnitureID不同；路径关联成功不代表库存身份相同。特殊笔刷Type=1表示植被、Type=2表示地表材质，不能与家具类型列混用。

资源路径中有11,793条`.mesh`、4,410条`.prefab`、289条`.group`以及其他类别。扩展名计数不是唯一文件数量，更不是已经解码的模型数量。空值保持原样，不当作零、无限或关闭。

```sh
# 五张输入表的相对路径见 tools/furniture-resource-paths.txt
python tools/build_furniture_index.py --assets ./client-assets --output ./docs
```

## 3. Mesh与GLB处理

`tools/inspect_mesh.py`对已核对的HSEM布局读取顶点位置、法线、UVW流边界和32位三角索引；检查文件长度、流范围与重叠、有限值、索引范围和数量。纯几何GLB默认按100坐标单位换算1米，保留形状，使用中性材质。

未压缩布局检查报告覆盖216个样本，其中180个满足该布局条件，其余36个保留各自的布局差异记录。地下室压缩布局另以144个形态核对，统计范围分别记录。用于本机预览的37份GLB覆盖桌椅、床榻屏风、灯饰、摆件、建筑、庭院和拼布基座，经Khronos Validator校验，错误及警告均为0。元数据记录见 `model-geometry-check.json`。

```sh
python tools/inspect_mesh.py 家具.Mesh --output 几何报告.json --glb 家具.glb
```

纯几何转换路径未包含原UV贴图、切线、材质子集、骨骼、动画、LOD或完整Prefab装配。能显示一个灯的网格，不代表发光、火焰、透明排序、附属节点和游戏光照已还原。源码随附部分经过压缩的材质 GLB，支持模型、内嵌贴图与样式的查看。

## 4. 两种预览的实现

### 拼布组件

`packages/core/src/scene.ts`读取实际导出文件，恢复本导出器的观察方向，按资源边长、厚度和文件变换建立实例批次。预览实例来自文件中的家具节点，观察操作不修改下载文件。所有已导出家具必须计数一致，未知资源会报错。

`preview.worker.ts`负责文件读取，`preview3d.ts`使用Three.js的InstancedMesh分批显示大量拼布。正交相机用于观察微缩遮挡，提供旋转、缩放、平移、正面/俯视、侧面、斜视、重置、结构线及放大查看。整棵树统一转换坐标约定，不能重复乘父缩放或随意改变图案左右方向。

基座用实际位置上的小型定位标记表示，可单独开关，标记不代表真实基座尺寸。琉璃显示已核对的轮廓；其叠色效果仍以回读的拼布效果图为参考。旋转看到的是真实厚度和层次，微缩图案从侧面未必保持完整图像。

### 家具模型

`furniture3d.ts`用GLTFLoader读取自包含GLB，支持相机观察、尺寸和结构线。模型引用的外部纹理/缓冲区URL被拒绝，所需资源必须嵌入GLB。要求额外解码扩展的模型先转成普通GLB。内置38份样本使用内嵌贴图、材质分区和染色方案；照明及部分特效采用网页近似。转换规则见[家具贴图与材质](21-furniture-materials.md)。

内置模型清单格式：

```json
[{ "file": "chair.glb", "name": "椅子", "category": "桌椅", "note": "单件预览示例。" }]
```

GLB和清单放在同一目录，然后执行：

```sh
node scripts/prepare-furniture.mjs 模型清单.json
pnpm dev
```

准备脚本将模型与完整清单保存到 `assets/models/furniture/`。静态网页与桌面构建直接包含模型；单文件离线 HTML 保留手动选择 GLB 的入口。资源接入和新增家具步骤见[内置模型库](24-model-library.md)。

两个查看器均按需加载、按交互重绘，静止时没有持续动画循环。切换工作区或隐藏页面暂停绘制；更换图片/参数销毁旧组件。WebGL不可用时，图片导出、2D预览和下载继续可用。

## 5. 扩展到完整家具和整屋编辑

### 资源流水线

```text
家具类型与ID → 表现资源表/样式
  → Mesh / Prefab / Brush / 树木 / 动画 / 特效处理器
  → 几何、子集、UV、材质、纹理及节点层级
  → 单位、坐标轴、法线、挂面校准
  → GLB + 资源映射清单 + 独立效果描述
  → 网页按需加载、缓存与实例化
```

每份转换模型应记录资源ID、Detail、输入哈希、转换器版本、坐标换算、包围盒、挂面和不支持项。Prefab需保留内建节点局部矩阵；展开层级时需保留挂接与编辑关系。压缩网格、蒙皮动画、LOD、多材质、透明贴图与游戏专用着色器需要独立处理，资源条目、可显示模型与可编辑家具分别记录覆盖范围。

### 编辑数据与保存

场景编辑器保存稳定编辑ID、资源目录绑定、变换、样式、地下室地板归属和撤销记录。扩展整屋编辑还需要任意父子对象树、挂接面映射及未知块保留。GPU实例序号不应当作家具身份。挂接父子关系、用户分组、撤销操作组分别管理。

移动、旋转、等比/非等比缩放先明确坐标空间，再按资源限制写回。一段拖动结束记为一次可撤销操作；取消恢复原值。未知字段和节点保留原始块，尚不能安全写回的部分只读，不能静默丢弃。

### 环境与灯光

家具材质、蓝图LightModel、设计场太阳/月光、天气和画质是不同层次。184字节兼容灯光结构不包含全部344字节运行时字段，IES路径和地址副本也不能直接移植到浏览器。网页可用中性照明核对模型；复现游戏效果还需要贴图通道、混合模式、阴影、环境探针及曝光的对应方案。

### 性能和拾取

按几何与样式组织实例批次，保留绘制实例到文件节点的映射。透明材料排序、深度和微缩遮挡单独测试。大场景需要视锥裁剪、LOD、纹理预算、资源取消加载、拾取加速和GPU资源释放；性能测试应使用明确数量、材质和设备条件的代表性场景。

## 6. 验收边界

| 项目     | 检查                                        |
| -------- | ------------------------------------------- |
| 资源关联 | 类型/编号、资源表、Detail和真实加载路径     |
| 几何     | 非对称图案、多个方向、实体边长和挂面偏移    |
| 编辑     | 修改后导出回读，撤销恢复，不丢未知字段      |
| 材质     | 固定环境下检查底色、透明、双面和法线        |
| 浏览器   | 无WebGL降级、取消旧任务、反复切换、离线资源 |
| 游戏     | 导入、摆放、移动、保存、重载分别核对        |

文件校验、GLB格式校验、网页可见结果和游戏内验收是四份不同证据，不能互相替代。
