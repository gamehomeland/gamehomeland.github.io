# 家园系统与扩展路线

本章汇总家园建造、场景显示与蓝图的模块关系。网页提供图像转拼布、绑定家具编辑和地块范围选择；同时提供4米、8米地下室组件的连铺及整屋导出；完整地形、碰撞与复杂预制体仍属于扩展范围。

首次接触这些名词时，先运行[四格结构示例](15-reading-homeland.md)，再用本章定位模块。回调阶段、不同分组机制和排错路径见[客户端操作与问题定位](16-client-operations.md)。

## 系统分层

| 层次           | 职责                                       | 实现入口                                                | 本项目对应部分                          |
| -------------- | ------------------------------------------ | ------------------------------------------------------- | --------------------------------------- |
| 家具目录       | 分类、家具 ID、模型 ID、规格、交互、缩放   | `FurnitureData`、家具分类与信息表                       | `data/`、`catalog.ts`                   |
| 资源与样式     | Mesh/Prefab、挂点、Detail、染色预设        | `ID_Model`、`Homeland_FurnitureColor`、`SET_DETAIL`     | 拼布、基座及绑定普通家具                |
| 对象树         | 实例、父子挂接、容器、局部变换             | `AddChild`、`_AttachAnchor`、`_Combine3DNodeSDKObject`  | `component.ts`、`layout.ts`             |
| 交互操作       | 选择、移动、旋转、缩放、多选、复制、拆除   | `HLBOp_Select/Place/Rotate/SingleItemOp/MultiItemOp`    | 家具与地下室编辑、资源及边界校验        |
| 地块与建造模式 | 场景尺寸、区域、设计与实地模式             | `HLBOp_Main/Enter`、`GroundArea`                        | 七档尺寸、108处社区地块和私宅7区        |
| 操作历史       | 一组操作、撤销和重做                       | `HLBOp_Step`、`START_GROUP/END_GROUP`                   | SceneHistory撤销与重做                  |
| 资源核算       | 库存、等级、分类/单种上限、存储与交互占用  | `HLBOp_Amount/Check`、`HLBView_ErrorItemList/Saveusage` | 统计导出清单，不代替玩家库存查询        |
| 蓝图与保存     | 文件、加载预览、局部组件、整屋、正式应用   | `HLBOp_Blueprint/Save`、原生蓝图加载保存函数            | V7局部组件、地下室整屋蓝图及文件回读    |
| 场景显示       | 材质、天气、时辰、直接光、反射、阴影、滤镜 | WeatherSetting、Filter_Base、模型像素与光照入口         | 固定色卡、材质预览和可见性校验          |

## 关键数据关系

```text
家具 ID ──→ 库存与清单
    │
    └──→ 表现资源 ID ──→ 模型 / 预制体 / 可用 Detail
                           │
                           ├── 材质与纹理 → 场景光照 → 屏幕颜色
                           └── 挂面与挂点 → 家具实例树 → 蓝图文件
```

资源ID标识型号，实例ID标识一次摆放产生的对象，Detail 选择该资源已有样式。内建模型、挂点容器和可购买家具也不是同一层对象。清单核算、复制、删除和选择操作均应使用对应层次的标识。

## 建造的生命周期

```text
选择建造模式与地块
  → 加载已有场景、目录与状态
  → 创建 / 导入 / 移动 / 旋转 / 缩放等编辑操作
  → 分类、单种、库存和存储占用核对
  → 用户确认摆放
  → 导出文件，或保存并应用当前家园
```

有未完成的临时操作时，不能并行开始任意新动作。撤销以操作组管理，导入文件与正式保存分开。实现网页三维编辑时，应先建立命令和事务层，再接场景对象，避免 UI 一次拖动造成多处数据不同步。

## 场景预设和实际地块

可用设计规格、社区实际四角、私宅7区与45,792平的组成见[地块规格与布局](22-land-layouts.md)。网页“选择户型 / 地块布局”可查看和选择这些范围。

`GroundArea.tab` 资料中的设计预设为：32×40、40×56、56×72、72×100，以及标记 `private` 的 56×112、104×112、212×216。它们是设计入口资料，不是任何账号都已拥有的地块范围，更不能由最大预设推导统一高度上限。

建造模式会把长宽和私人地块条件传入初始化；容量、库存和权限仍要结合实际模式判断。具体检查见 [蓝图导入与家园限制](10-game-limits.md)。

## 功能扩展入口

### 仅优化图片转蓝图

继续使用 `exportImage` 和 `createPackage`，优先修改采样、配色候选和质量评价。每种颜色都必须落到真实家具组合；复杂候选需要比较实际家具成本与轮廓损失。参阅 [导出流程](05-export-pipeline.md)。

### 扩展三维预览

先回读 `.blueprintx`，从真实家具变换建立场景；分开实现模型可见性与材质显示。最小版本只需要固定相机和受控照明，之后再加入天气、阴影、环境反射。参阅 [光照与场景](11-lighting-and-scene.md)。

### 扩展场景编辑器

建立对象树、选择集和操作组，支持移动、旋转、等比缩放以及撤销。每次操作保留局部坐标与世界坐标的明确边界；移动整组时保持挂接关系。先限制在已经支持的节点类型内，再逐种扩展。

### 扩展成通用蓝图查看器

应用编解码器按功能限制支持的节点；独立检查器的读取范围更广。扩展查看器时，应先补齐未支持节点的数据结构和文件样例，再接入界面。未知类型没有通用长度，解析需在该位置停止。

### 容量规划与清单工具

清单先统计可购买家具实例，再结合外部提供的库存、分类上限与单种上限。没有玩家数据时只给需求清单，不应显示“保证可保存”。存储单位和件数必须分开，说明来源与当前验证范围。

## 资料组织约定

资料按以下三类组织：

- **运行资料**：导出真正需要的家具编号、尺寸、挂点和颜色数据。
- **开发证据索引**：路径、哈希、函数名、字段和核对结果，便于更新时发现变化。
- **验证样例**：输入、参数、真实蓝图、回读预览、清单和游戏内结果。

本仓库提供运行资料、证据索引、程序验证样例和部分模型 GLB；GLB 内嵌所需贴图。二次开发者可按自己的目标补充资源与实景验证记录。
