# 导入、撤销、家具核算与保存

本章说明蓝图导入、编辑状态和保存流程，依据为客户端 `HLBOp_Blueprint`、`HLBOp_Check`、`HLBOp_Amount`、`HLBOp_Step`、`HLBOp_Save` 的操作链；它们与原生 `KRLHomelandBuilder` 通过 `Homeland_SendMessage` 交互。

请求的直接返回只说明当前调用的结果；完整数据可能随后通过 `HOMELAND_CALL_RESULT` 分阶段到达。例如消耗查询分别清空暂存、追加记录、完成更新。局部放置还要等玩家确认。各阶段与排错入口见[客户端操作与问题定位](16-client-operations.md)。

## 1. 导入生命周期

```text
选择文件
  → 清除选择，取消正在放置的模型、笔刷和多选移动
  → 开始 LoadBlueprint 操作组
  → START_LOAD_BLUEPRINT：检查并准备
  → LOAD_BLUEPRINT：建立对象，进入加载状态
  → 移动预览 / 确定摆放 / 取消
  → END_LOAD_BLUEPRINT：结束加载
  → 结束操作组，刷新家具与场景状态
```

`StartLoadBlueprint` 会清理当前交互状态并记录路径。`LoadNormalBlueprint`、`LoadMoveBlueprint` 使用不同模式标记，但都先设置修改状态，并在请求成功后标记“正在加载”。文件读取、对象创建和摆放确认分别对应独立阶段。

`MOVE_LOAD_BLUEPRINT` 接收鼠标位置来更新放置位置。整体摆放取消需要结束当前加载流程并清除暂态数据，不能只隐藏预览窗口。

## 2. 操作互斥与保存前置条件

`HLBOp_Check.Check` 和 `CheckClickItem` 检查正在移动蓝图、加载文件、移动笔刷、多选移动、拆除及家具消耗查询等状态。某些状态下禁用新操作，是为了避免两个未完成操作同时修改场景。

`CheckSave` 除了检查是否修改，还核对：

- 当前是否处于相关快捷键操作中；
- SDK/场景大小与场景对象限制；
- 家具错误列表是否为空。

若家具核算有错误，编辑器可以引导查看错误列表或先导出文件。**能导出局部文件，不等于拥有足够家具把它保存为正式家园。**

## 3. 撤销与重做机制

`HLBOp_Step.StartOneStep`、`EndOneStep` 对应 `START_GROUP`、`END_GROUP`，把多次底层变更合为一个操作步骤。导入一整组家具可以作为整体撤销。

点击撤销或重做时，Lua 先发送 `OP_UNDOABLE` 查询可操作步数，收到回调后再发送 `UNDO` 或 `REDO`。成功后刷新地块家具数据与分组信息。清理暂态操作还有专门的 CLEAR、WITHOUT_REFRESH 分支，不应把它们当成同一个用户动作。

导出器应维护完整、稳定的组件树及操作边界。独立家具实例的集合不会自动形成同一个撤销事务。

## 4. 场景对象与家具清单核算

`HLBOp_Amount` 通过 `FurnitureData.GetFurnTypeAndIDByModelID` 把表现模型映射回家具类型和家具 ID，再调用家园管理器的加载、增加、查询接口进行核算。刷新时会查询消耗、可交互对象、花草/地表笔刷等不同类别。

一个预制体可以包含多个内建网格和挂点，但不应把每个节点都当成一件需要购买的家具。反过来，多次放置同一表现模型，也不能因为资源 ID 相同就只计一次。

本工具按支持的拼布、基座、普通家具及地下室组件统计实例需求；玩家已有库存、其他笔刷和交互对象成本仍由游戏核算。

## 5. 蓝图导出、保存家园与自动保存

| 动作                 | 对应机制                               | 结果                         |
| -------------------- | -------------------------------------- | ---------------------------- |
| 导出蓝图或局部组件   | `SAVE_BLUEPRINT`，局部模式还带目标对象 | 一份可再次导入的文件         |
| 保存当前家园         | 保存检查、`SAVE` 与后续应用流程        | 尝试把编辑结果保存到当前家园 |
| 设计模式自动保存     | `AutoSaveBlueprint`                    | 保存设计蓝图                 |
| 其他建造模式自动保存 | 通过 `SAVE` 写备份路径                 | 对当前编辑工作进行备份       |

`HLBOp_Save.DoAutoSave` 会先检查模式和操作状态，不是任何时刻都无条件写入。`DoApplyBak` 还调用家园管理器应用建造结果，并处理后续等待和失败提示。工具输出`.blueprintx`文件；家园应用和自动保存由游戏流程处理。

## 6. 文件格式之外的限制

导入与保存包含文件读取、交互状态、家具核算、场景大小和对象限制等检查。没有游戏实现证据的数值，本文不补成“固定上限”。`uint16` 子节点计数和工具处理预算均不用于推导玩家容量。

本文覆盖客户端操作链。完整服务端校验、不同家园权限和全部建造模式不属于本文的验证范围。
