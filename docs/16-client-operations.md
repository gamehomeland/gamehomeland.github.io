# 客户端操作、回调与问题定位

本章说明模块职责、操作阶段与故障定位方法，供查看器及组件编辑器开发参考。内容来自所核对的客户端操作链、原生文件入口和本项目代码；服务端内部规则没有由这些材料完整覆盖。

## 1. 模块职责与资源入口

| 分析目标             | 资源或模块                              | 观察重点                                          |
| -------------------- | --------------------------------------- | ------------------------------------------------- |
| 家具与模型对应       | `ui/Script/FurnitureData.lua`           | `GetFurnTypeAndIDByModelID`返回家具类型和家具编号 |
| 文件选择、分类与导入 | `BuildingOperation/HLBOp_Blueprint.lua` | 查询全局标记、准备、加载、移动、结束和结果分支    |
| 放置局部组件         | `BuildingOperation/HLBOp_Place.lua`     | `StartBlueprintPartPlace`与确认、取消流程         |
| 当前操作是否允许     | `BuildingOperation/HLBOp_Check.lua`     | 当前状态、家具核算、保存条件                      |
| 消耗和场景统计       | `BuildingOperation/HLBOp_Amount.lua`    | 请求、暂存、结束阶段发布结果                      |
| 编辑器分组           | `BuildingOperation/HLBOp_Group.lua`     | 分组成员的查询和缓存更新                          |
| 撤销与重做           | `BuildingOperation/HLBOp_Step.lua`      | 操作组与可撤销步数                                |
| 保存与应用           | `BuildingOperation/HLBOp_Save.lua`      | 设计保存、备份与应用流程                          |
| 缩放、高度、颜色界面 | `BuildingView/HLBView_ItemOp*.lua`      | UI范围、资源条件与实际操作请求                    |
| 天气与时辰           | `HLBView_WeatherSetting`、`HLBOp_Other` | 环境查表、场景切换及退出时恢复                    |

表中的 `BuildingOperation/` 和 `BuildingView/` 位于 `ui/Config/Default/Homeland/`。原生部分对应`KRLHomelandBuilder`的加载、保存、节点和挂接函数；模块哈希与定位入口见 `client-evidence.json`、`game-limits-evidence.json`。地址只对相应模块有意义，不能当跨版本接口。

项目提供实现说明、工具和证据索引。`implementation-reading-map.json`列出本章回调与分组结论的资源哈希和函数入口，方便二次开发者独立复核。

## 2. 请求与分阶段回调

`Homeland_SendMessage`的直接返回、后续回调、玩家确认，是三个阶段。以家具消耗查询为例：

```text
RequestConsumption
  → 发送GET_ALL_CONSUMPTION
  → 请求受理后设置“查询中”
  → HOMELAND_CALL_RESULT按阶段传回数据
  → 结束阶段更新家具数据并清除“查询中”
```

所核对的 `OnRequestConsumptionResult` 按以下阶段组织数据：

| phase | 阶段行为                                         | 此时能否把暂存列表当最终结果 |
| ----- | ------------------------------------------------ | ---------------------------- |
| 0     | 记录开始结果，清空暂存容器                       | 不能                         |
| 1     | 把本次返回的消耗记录追加到暂存容器               | 不能，后面可能还有记录       |
| 2     | 按请求用途加载或刷新家具数据，清空暂存并结束查询 | 正常完成后可使用             |

上述阶段值仅适用于该回调协议。其他消息即使也有 `arg1/arg2`，字段用途也可能不同，不应建立“所有回调第二个参数都是phase”的规则。

编辑器可采用以下状态模型：“请求中 → 收集结果 → 完成或失败”。每次请求应有清晰的状态归属；失败和取消必须清理暂存数据。该状态模型属于工程设计建议，不扩展未核对的游戏分支结论。

## 3. 蓝图导入阶段

| 阶段     | 所核对行为                                      | 开发者要区分的结果                 |
| -------- | ----------------------------------------------- | ---------------------------------- |
| 选择     | 选择有效文件，查询是否为全局蓝图                | 路径存在不代表格式正确             |
| 准备     | 清除选择和已有放置操作，开始LoadBlueprint操作组 | 清理旧操作不代表新对象已建立       |
| 检查     | 原生入口检查文件头、版本、尺寸等适用条件        | 整屋与局部进入不同分支             |
| 加载     | 读取节点、资源和变换，回调传递对象资料          | 返回对象编号仍可能需要进入放置过程 |
| 局部放置 | 汇总型号与数量，调用`StartBlueprintPartPlace`   | 玩家仍需确定位置或取消             |
| 结束     | 结束相应加载模式，更新消耗、分组与界面          | 结束导入不等于已正式保存家园       |
| 保存     | 检查修改状态、错误清单、占用和实际目标          | 保存及应用结果单独处理             |

`OnLoadBlueprintResult`会根据是否有局部对象编号、当前加载模式和阶段分支处理。局部组件路径会汇总返回型号，再交给放置操作。不要把整屋分支中的清空历史、场景尺寸比较等动作，原样套在局部拼画上。

原生 `StartLoadBlueprint`有一个准备分支会检查全局标记和两轴场景尺寸；相应Lua回调还处理继续普通加载等返回值。单看某个返回数字，容易误判成所有导入都失败。应同时记录操作名称、模式、阶段和返回值，并结合调用方解释。

## 4. 分组机制与数据边界

| 名称                | 职责                             | 结构与生命周期约束                    |
| ------------------- | -------------------------------- | ------------------------------------- |
| Prefab / GroupModel | 一个资源预先定义的组合及内建成员 | 保留资源定义及内建成员                |
| 父子挂接树          | 连接关系与局部变换               | 父子关系独立于选择集                  |
| 编辑器分组          | 多个对象作为一组选择和管理       | `HLBOp_Group`有独立成员查询与缓存     |
| 撤销操作组          | 把一批操作组织成一个撤销步骤     | `START_GROUP/END_GROUP`是操作记录边界 |

`HLBOp_Group`使用 `PACKUP_MODEL_GROUP`、`UNPACK_MODEL_GROUP`、`DESTROY_MODEL_GROUP`等消息，结果写入 `m_tGroupInfo`。`HLBOp_Step`使用 `START_GROUP/END_GROUP`，撤销前还查询 `OP_UNDOABLE`。两者使用独立的数据结构和生命周期。

对组件编辑器，至少要分别保存场景对象树、用户选择集和操作历史。例如移动三件家具时，需要记录三个实例的变换变化；是否属于一个预制体、是否挂接、是否组成一个撤销步骤，应由各自规则决定。

## 5. 资源与保存条件核算

```text
表现模型实例
  → 家具类型与家具编号映射
  → 按实例汇总需求
  → 对照当前库存、等级、分类容量和单种上限
  → 核算存储、交互对象和保存数据占用
  → 保存或显示具体错误
```

不能按“不同resourceId的个数”计算家具数量，也不能按总节点数购买家具。预制体内建网格、空挂面与Holder都需要按其角色处理。交互对象、花草笔刷、地表笔刷还走各自查询路径，本工具的拼布清单没有覆盖它们全部成本。

容量表、保存数据阈值和家具数量不在同一量纲。规则及比较符号见[家园限制](10-game-limits.md)；不要把存储占用单位直接显示成“还能放多少件”。

## 6. 故障定位

| 现象                     | 优先检查                                       | 建议保存的证据                        |
| ------------------------ | ---------------------------------------------- | ------------------------------------- |
| 文件打不开               | 版本、局部/全局标记、长度和摘要                | 原文件、SHA-256、检查器报错偏移       |
| 读到某节点后全部错位     | 资源对应的缩放维数、空挂点、可变字符串与块长度 | 最后成功字段和紧随其后的字节          |
| 清单数量明显不对         | 内建成员是否重复计费、是否按实例计数           | 节点类型、builtin、资源映射与需求清单 |
| 图案旋转、镜像或位置偏移 | 图像坐标、模型局部面、挂面变换、导入朝向       | 非对称测试图和回读变换                |
| 预览正常，侧面看破碎     | 微缩遮挡与观看角度                             | 正面、侧面、实体包围盒和尺寸          |
| 能看到但无法保存         | 库存、等级、分类、单种、存储和交互占用         | 游戏错误清单和对应操作阶段            |
| 颜色发灰或与游戏不同     | 材质、线性空间、法线、光照、天气和显示变换     | 同一蓝图、固定场景与画质下的取样      |
| 透明材料消失或遮住底图   | 单/双面、朝向、形状、深度与透明混合路径        | 实际资源、变换、可见性与实景截图      |
| 操作按钮无响应           | 是否仍在加载、放置、消耗查询或其他互斥状态     | 操作名、状态变化和完成/失败事件       |
| 重载后位置或样式不同     | 是否完成正式保存、导入方向或显示样式处理       | 保存前后文件、Detail及相同视角截图    |

故障处理应先定位层次和复现条件。格式校验、数值容差和未知节点处理规则须保持明确，修复结果应通过回归验证。
