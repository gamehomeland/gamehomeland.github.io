# 验证范围与复现方法

## 验证层级

| 层次                 | 验证内容                                   | 范围限制                     |
| -------------------- | ------------------------------------------ | ---------------------------- |
| 客户端资源与原生函数 | 编号、挂点、材质输入、序列化字段和相应分支 | 服务端规则、任意场景最终渲染 |
| 蓝图及程序验证       | 字节往返、变换、可见家具、清单、输出一致性 | 游戏实际导入、移动和保存     |
| 游戏内验收           | 当前客户端、地块、家具条件下的实际使用     | 所有玩家配置、未来客户端版本 |

本工具导出结果中的 `gameImportVerified` 固定为 `false`。程序运行成功不会自动把它改成游戏验收通过。

## 自动测试

在项目根目录运行：

```sh
pnpm install --frozen-lockfile
pnpm check
```

测试覆盖颜色标准样例、组件字节一致性、微缩几何、材料预算、PNG与ZIP内容，以及家具变换、地块边界、地下室连通、地板挂接和损坏输入处理。`tests/fixtures/layout-contracts.json` 保存确定性几何样例的字节摘要。

研究用字段检查器另外运行 `python tests/inspect_blueprint_test.py`，覆盖所有节点类型、可变全局块、资源决定的缩放布局、长度与校验错误。`node --import tsx examples/export-material-board.ts` 生成彩色材料试色蓝图并验证编号、合法缩放和位置回读；两项都不代替游戏内验收。

进一步生成实际样例：

```sh
pnpm samples
```

样例由程序生成，包含墙面、地面、小尺寸、大尺寸、透明边缘、文字与渐变。`artifacts/samples/` 输出真实蓝图、预览及清单，可用于导入游戏和比较不同配色或布局算法。

## 游戏内核对顺序

1. 先导入小型普通布局，确认家具数量、左右方向、上下方向和成品米数。
2. 再导入小型微缩布局，从墙面正前方或地面上方查看轮廓，移动视角观察边缘。
3. 整体平移和旋转组件，确认挂接不散，清单不发生异常变化。
4. 保存家园，退出编辑后重新进入，比较颜色、姿态和基座显示。
5. 在实际地块条件允许时再试大尺寸和高家具量，记录帧率与容量提示。
6. 分别测试根基座显示与隐藏，确认整体选择以及编辑器显示开关的影响。

初始游戏验证应使用低家具量的小尺寸样例；通过后再扩展到更高计算预算。工具处理预算与游戏容量分别核对。

## 资料变化时的核对项目

- 客户端版本及资源哈希是否变化。
- 拼布的家具 ID 与表现 ID 是否仍一一对应。
- 挂点顺序、模型平面方向、尺寸和缩放范围是否变化。
- 纹理是否仍均匀、着色器的透明度规则是否变化。
- 文件版本、字段布局和校验算法是否变化。
- 确定性样例能否编码解码，已有游戏验收是否需要重做。

资料缺失或格式变化时停止生成，保留完整的可用资料集。一次导出使用一致的资源版本，缺项需补齐并完成核对后再更新。

## 问题报告要求

问题报告应包含工具版本、游戏环境、功能入口、输入参数、复现步骤及错误信息。图片转换补充尺寸、方向和家具预算；家具布置补充地块、地下室规格及挂接关系。可附去除个人信息的样图、最小工程或蓝图。
