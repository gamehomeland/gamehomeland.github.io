# 材质、透明度和颜色

## 1. 颜色处理流程

家具编号对应模型、材质、纹理和染色参数。由它们得到线性反照率，再经过照明、透明混合与显示变换，才成为屏幕颜色。

图标是已经渲染完成的小图，会带有自身的光照和背景。工具保留图标采样供核查，选色使用材质参数推导的中性显示基准。

## 2. 材质数据读取

每种拼布的两种规格分别核对模型、材质、纹理、挂面和缩放范围。基础纹理、材质染色参数与混合方式共同决定线性反照率。不同规格的颜色参数必须一致，才能归为同一种颜色。

线性颜色保存在 `linearColor`，图标观察值保存在 `iconRgb`。两者用途不同。当前有 71 种不透明底色及一种透明叠层。

## 3. 中性显示基准

资料生成器核对游戏 `CommonParam.h` 中的 `Tonemap` 及其调用点。选定分支使用下面的显示变换：

```text
x = max(0, 2^exposure × linearColor - 0.004)
display = x × (6.2x + 0.5) / [x × (6.2x + 1.7) + 0.06]
RGB8 = round(clamp(display, 0, 1) × 255)
```

调用点的 `exposure` 为 0.5。生成器检查函数形式和调用参数；来源变化时要求重新核对，不会静默继续套用旧公式。

**使用范围：**该函数在游戏的低档前向渲染分支中调用。本工具以单位白色照明构造固定预览基准，墙面、地面共享它。该基准不包含完整场景渲染，适用范围限于所选光照与显示条件。参数及范围写入资料文件的 `display_transform`。

变换结果属于选定模型的显示空间，后续应避免重复 gamma 转换或按单张图片修改亮度基准。预览和家具选色使用同一套基准。

## 4. 透明叠色

透明层的基础不透明度由材质与纹理规则得到。当前灰1的纹理 alpha 取值为 128/255，对应材质取样后的基础不透明度为 `(128/255)^2.2`。

中性预览先在线性颜色上估算叠层：

```text
C_out = alpha × C_layer + (1 - alpha) × C_under
```

再对组合色使用同一显示变换。普通布局在底色上最多叠 5 层透明拼布，共有 `71 × 6 = 426` 个配方。它们来自相同的真实家具组合，主要补足浅色和灰阶；不代表426种家具，也不能扩出原材料无法达到的饱和色。相同或非常接近的显示颜色可能对应不同配方。

六层上限属于本工具在质量与用量间的选择。需要更多家具却没有足够色差改善时，会自动选择较少层数；实际用量包含全部透明层和基座。

这是固定条件下的叠层估算。不同渲染路径中的透明排序、阴影与后处理仍需游戏内验证；程序不会自动标记为实景验证通过。

## 5. 自动选择配方

- 使用 Lab 空间的 CIEDE2000 色差，并保护中性色、暗部和色彩关系。
- 缩图后进行轻微局部边缘补偿；平涂区域清理压缩造成的细小噪声。
- 透明叠层需要带来足够改善才加入，并计入真实家具数量。
- 同时比较整体色差、轮廓、明暗和新增颗粒，避免只让某个局部误差更低。
- 微缩布局和像素画的底层使用不透明拼布。8米高精度墙画通常采用微缩，普通布局的426个叠层配方不能直接套入；试验扩色使用独立前置透明层，并单独验证覆盖范围。

每个颜色配方均对应可导出的家具及叠层。效果预览由最终蓝图回读生成，与导出布局使用相同数据。家具色域有限，照片中的连续颜色仍可能出现色阶。

## 6. 显示校准流程

使用中性灰、纯色、渐变和实际图片，在固定画质、天气、时辰、距离、方向下核对。先比较原图与文件回读效果，再比较实际摆放截图。记录条件，逐步完善照明模型。

不同条件下的游戏截图不能直接混成同一张色表。任何新的校准数据都应保留依据、计算方式和验证范围。

彩色透明材料的分区配色、试色蓝图和验证范围见[扩展材质配色](14-material-expansion.md)。配色数据与家具几何配套；材质参数不能单独代替可导出的家具。
