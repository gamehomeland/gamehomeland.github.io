# 家园模型、挂接和尺寸

蓝图记录家具实例、资源关联和空间变换。图像转换将目标颜色映射为家具组合，并按采样网格生成位置、旋转、缩放及组件层级。

[四格组件示例](15-reading-homeland.md)提供5件家具、17个节点和478字节文件的结构对照。本章说明资源层次、坐标与变换。

资源索引、模块哈希和函数位置见 `client-evidence.json`；函数地址使用模块内 RVA，不是每次启动都固定的内存地址。

## 1. 家具标识与资源编号

| 层次         | 用途                         | 例子                         |
| ------------ | ---------------------------- | ---------------------------- |
| 家具编号     | 玩家仓库、购买和家具清单     | 根基座家具 ID 6551           |
| 表现资源编号 | 在蓝图中选择模型或预制体     | 根基座资源 ID 18230          |
| 内部网格编号 | 预制体包含的可见网格         | 资源 ID 18238                |
| 实例编号     | 区分同一蓝图内重复放置的家具 | 每次放置生成一个唯一编号     |
| 挂接索引     | 选择父模型的某个挂面或挂点   | 由 `.Mesh.jsonAP` 的顺序决定 |

家具编号不能直接代替表现资源编号；同一件家具的内部网格也不应在清单中重复计费。导出器按实际拼布实例与基座预制体统计材料，不把 Holder 和挂点容器当家具。

## 2. 蓝图对象树

```text
Holder：可整体移动的局部组件
└─ GroupModel：根基座预制体
   └─ Model：预制体内建网格
      └─ PlaneContainer：网格的挂面
         ├─ Model：拼布
         │  └─ PlaneContainer：拼布自己的挂面
         │     └─ Model：其他拼布
         └─ GroupModel：下一组基座
```

`_Combine3DNodeSDKObject` 按预制体资源递归生成内建成员；`_AttachAnchor` 按资源的挂接定义建立容器。`AddChild` 则改变父子关系：从旧父节点移除、加入新父节点、更新关联状态，并防止形成祖先循环。它使用可扩展数组保存子节点。

父节点缩放与已序列化子节点偏移的组合规则取决于导出器的坐标约定。本工具生成布局时已将挂面偏移所需尺度写入文件；回读这类组件时按已归一的偏移合成旋转和平移。如果再沿每级父节点乘一次缩放，会把拼布间距错误压小。该回读规则的验证范围是本工具的拼布组件，不能直接推断任意非等比家具也适用。

## 3. 拼布规格与缩放换算

客户端模型中，2 米拼布的 X/Z 边界约为 `[-100, 100]`。结合家具表的规格，可得该资源使用 **100 坐标单位 = 1 米**。

```text
2 米规格 × 0.25 等比缩放 = 0.5 米
0.5 米 × 100 坐标单位/米 = 50 坐标单位
```

家具表提供每个规格的缩放范围。原生缩放校验还区分允许非等比的资源和普通资源，分别包含 `0.1～10` 与 `0.25～2` 两组阈值，以及异常变换修正分支；具体范围取决于资源类型。本工具逐件使用家具表中的范围。

文件保存的是 float32。排布时的双精度计算必须经过一次实际编码、解码再验证，才能发现取整、浮点舍入造成的位移，而不是只验证尚未写进文件的理想坐标。

## 4. 分组与容量

对象树按组组织家具，便于整体移动与管理。直接子节点数量以 `uint16` 保存，运行时使用可扩展数组；字段可表示的节点数量与地块家具容量分别校验。

对象树、资源预制体、用户分组和撤销操作组分别维护独立语义。`HLBOp_Group`管理成员查询，`HLBOp_Step`管理操作记录；同一父节点、同一选择组和同一个撤销步骤不互相等价。详见[四种组的区别](16-client-operations.md)。

导出器按 `component.ts` 的 `GROUP_SIZE` 分组，并把所有基座计入家具预算。调整分组策略后要重新核对树结构、位置回读和清单。游戏仍会检查地块容量、已有家具与场景限制。

## 5. 墙面与地面的坐标转换

拼布自身的平面是 XZ 面，局部 Y 是厚度方向。墙面画将该平面旋转至竖直方向；地面图案按目标观察方向映射图像行列。

文件以四元数 **XYZW** 保存旋转。四元数相乘不可交换顺序。工具分开处理：图像行列坐标、家具局部变换、挂接树变换、组件导入朝向补偿。测试会将文件回读到目标平面逐格比较，不以预览正向代替文件验证。

## 6. 整体操作基座

根基座资源 18230 的预制体含有网格 18238。其内部缩放为 `0.5`，Y 平移为 `1` 个游戏坐标单位；这不是 1 米。

基座承载挂接树，并提供整体选择与移动的参照。导出器根据墙面或地面调整其姿态；基座自身的显示样式与拼布的实际位置分别控制。

客户端模型资源包含 `TransparentBase`、`InitHide` 标记。`_SetDetail` 改变显示样式；`_ShowTransparentBase` 和 `_SetInitHideModelVisiable` 也能改变编辑器中的显示。**文件中的可见性和编辑器当下的显示开关可能不同。**

“显示整体操作基座”只修改根预制体及内部网格的 Detail，不删除挂接树。隐藏选项经过文件差异和几何验证；游戏内编辑模式是否重新显示、整体选择是否便利，仍要实际导入核对。默认保留显示。

## 7. 采样精度与实体尺寸

当图案间距小于合法拼布实体边长时，工具采用微缩布局：实体保持合法缩放，通过轻微倾斜与重叠，让正面可见区域形成更密的颜色格。

因此存在三个不同量：原图像素数、画面可见格数、家具实体边长。缩小成品米数不一定要同比降低格数，但会改变遮挡、厚度和最佳观看方向。微缩不是修改游戏允许的最小缩放，也不是任意视角都平整的贴图。

四象限布局、约 1° 微倾和实体包围盒控制属于本工具策略，客户端提供的是合法模型、变换及渲染能力。
