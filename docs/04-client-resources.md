# 游戏资源与材质

## 资源链

```text
Homeland_FurnitureCatg.tab → “拼布”分类
Homeland_FurnitureInfo.tab → 家具ID、模型ID、名称、2/4米、缩放范围
Represent/homeland/ID_Model.txt → Mesh 或 Prefab、Detail、标签
FurnitureAddInfo.tab → 对应的家具图标
Mesh → 顶点流、尺寸、表面高度
Mesh.jsonAP → 挂面顺序、标签、中心、变换
jsoninspack → 材质参数与渲染状态
jsondef → Shader 引用
fx5 + dds(CRN/BC) → 纹理值及颜色/透明度计算
```

`tools/extract_client_palette.py` 按表取必要文件，输出到新的离线目录；不会在项目中安装游戏 DLL。读取器调用已安装客户端的导出读包接口，编译和提取均在 Windows 进行。客户端有更新时先核对签名、接口和版本，不使用固定函数地址猜测调用。

生成器读取 593 个输入，输出四份 JSON。每个资源记录大小与 SHA-256，更新过程中不得混用不同版本。任何型号缺失、数量变化、图标帧变化、模型尺寸变化、非均匀纹理或未知着色器规则都需重新审核。

## 颜色

- 72 种颜色中，71 种不透明，灰1透明；每色有2米、4米规格。
- 基础配色由材质的线性反照率经过选定显示变换得到。两种规格的图标采样继续保存为核对记录，不作为选色的显示颜色。
- 显示变换来自 `CommonParam.h` 的 `Tonemap` 与 `ModelBasePixelShader.fx5` 中的调用点。按固定中性照明生成配方，不代表所有游戏环境。
- 拼布基础贴图是空间常量 `[255,255,255,128]`，着色器对采样值做 2.2 次幂。普通材质 BlendMode 0 按不透明处理；灰1 BlendMode 12 的基础 opacity 为 `(128/255)^2.2`。
- 透明灰图标包含背景，不能将其采样色当透明层本体色。叠层使用材质线性参数和基础不透明度估算，再经过统一显示变换。
- 共生成 `71 × 6 = 426` 种底色加0～5层灰1的配方，普通布局按颜色改善和用量自动选取。微缩和像素画使用 71 个底色。六层上限是本工具策略，不是游戏叠层极限。

## 挂点

每件拼布读取自己的 `.Mesh.jsonAP`，按 `H_Furniture`、朝上法线和正表面中心选择顶部挂面。144 个规格逐一核对索引及高度。

根基座从 `reverse_1x1.prefab` 的内部矩阵解析：网格18238缩放0.5、平移Y=1；其 `.Mesh.jsonAP` 的H_Furniture挂面中心Y再乘内部缩放，得到 `0.0000635000033`。这些值存于 `support_geometry.json`。

**根基座的型号、位置和显示方式属于导出策略。** 本工具使用悬·1×1米，依据其资源身份、挂面和样式构建组件；其他布局可采用经过验证的不同策略。

## 生成的数据文件

| 文件                           | 内容                                                 |
| ------------------------------ | ---------------------------------------------------- |
| `furniture_palette.json`       | 每色基准 RGB、实际家具规格、模型 ID、缩放与挂点      |
| `client_color_profiles.json`   | 线性叠色得到的配方表与中性色索引                     |
| `support_geometry.json`        | 根基座的内部模型、缩放、位移和挂面                   |
| `client_palette_manifest.json` | 资料版本、593 项输入大小与 SHA-256、生成文件 SHA-256 |

`scripts/build-catalog.mjs` 构建前核对生成文件哈希，再生成网页使用的精简资料。浏览器不需要读取游戏安装目录。

## 数据更新流程

1. 在装有客户端的 Windows 机器编译 `tools/read_client_assets.cpp`。
2. 使用 `tools/extract_client_palette.py --help` 查看提取参数，从指定客户端提取最小资源集。
3. 使用 `tools/build_client_palette.py --help` 查看生成参数，构建到一个新的输出目录。
4. 对照 manifest 审核变化，执行全套测试和实际导入。
5. 将四份 JSON 作为一个完整版本更新，再运行 `pnpm catalog`。

工程提供数值资料、文件哈希、资源读取工具和实现说明，可按资源目录复核。读取工具通过文件接口取得所需资源。

## 原生函数定位

`docs/client-evidence.json` 给出所核对模块的 SHA-256、关键 RVA 及部分资源哈希。优化编译可能产生跳板和实际函数体分离：定位时应同时核对模块版本、跳转目标和调用链，不把单个地址当跨版本接口。相关证据仅用于静态分析，导出工具运行时不调用这些原生 RVA。
